# θ 실험 로드맵 — A(AI)·B(시뮬) 공동, 단계별 계획 (2026-09-04)

지라: S15P21A106-135 종료 후 계획. 근거: [AI입출력명세서](../../5_Docs/AI/AI입출력명세서.md) §1·§2·§11,
[아키텍처 검토](2026-09-04_시스템아키텍처_검토_B트랙관점.md) §2-3·§2-4, [고부하 판정](2026-09-04_고부하_무릎_판정.md),
A트랙 -127(Optuna θ 탐색 워커), -128(합성 창고).

## 0. 한 문장

Optuna는 "정답 θ를 찾는 도구"이지 결론이 아니다. 최종 질문은 **"견적 한 건에 시뮬을 몇 번 돌릴 수 있을 때, 어떤 방식이
처리량을 가장 올리는가"** 이고, 그 답은 같은 테스트 창고 세트에서 모든 방식을 우리 시뮬로 채점한 표 하나로 낸다.

## 1. 단계

| 단계 | 담당 | 하는 일 | 끝나면 나오는 것 | 여기서 내리는 결정 |
|---|---|---|---|---|
| **0. 기반 맞추기** | B | 시뮬 실행 계약 문서(CLI·환경변수·SUMMARY 키·종료 코드·실행 시간). 성능 최적화(헤딩 28대 60~90 s → 목표 ≤ 15 s, 결과 비트 동일). 헤딩 모델 기본값 전환 | 계약 문서, 빠른 시뮬 | 견적 1건당 시뮬 호출 예산(횟수·시간) — 백엔드와 합의 |
| | A | -127 develop 리베이스, `--heading`·`--order-gap` 반영, 실행 시간 재측정 | 최신 시뮬에 붙은 워커 | 탐색 조건(대수·주문 간격·시드 수) 확정 |
| **1. θ 신호 확인 (wallA 한 창고)** | A+B | 고부하 조건(간격 15틱, 20~28대, 헤딩)에서 θ 감도: 파라미터 하나씩 바꿔 처리량 변화 측정 → 영향 없는 θ 식별 | 감도 표 | 탐색 차원 축소(11 → 실효 개수). 목적함수(tasks_per_h vs 리드타임 vs 혼합) |

| **3. 데이터셋** | A (-128) | 합성 창고 N개(랙 배치·통로 수·스테이션 위치 변주) × 운영조건 M개 → 각각 정답 θ (2단계 탐색기로). from_theta 토폴로지 추출 일반화 필요 | (창고×조건, θ, KPI) 쌍 수백~수천 | N·M 규모 = 시뮬 예산으로 역산 |
| | B | 합성 창고에서 시뮬·from_theta가 깨지지 않게 토폴로지 추출 일반화 지원 (현재 wallA 좌표 상수) | 일반화된 extract_topology | |
| **4. 방식 비교 실험** | A+B | 테스트 창고(학습 미사용)에서 아래 6가지를 같은 시뮬로 채점 | **핵심 표** (§2) | "AI가 필요한가, 어떤 형태로" |
| **5. 서빙 형태 확정** | A+B+백엔드 | 4단계 표에서 예산 안 최고 방식을 견적 엔진에 연결. B-5 스윕(θ 적용 vs 미적용, 대수별) 문서화 | 견적 엔진 θ 경로, B-5 문서 | 발표용 "왜 AI를 썼나" 근거 |

**3단계 갱신(2026-09-08, S15P21A106-139)**: 합성 창고 생성기가 나왔고, **"토폴로지 추출 일반화 필요"라는
전제가 이 경로에서는 빠진다** — 생성기가 레이아웃과 토폴로지를 같이 내므로(맵 세트의 `topology.json`)
B 의 `extract_topology` 일반화를 기다리지 않는다. 데이터셋 기본 변주는 랙 기하 3축(통로 개수·간격·길이,
조합 112)이고 밴드·스테이션은 wallA 로 고정한다. wallA 자체가 이 가족의 원소(`r11p6l21`)라 실험 6-(ii)
"합성으로 학습 → wallA 로 평가"에서 기하가 어긋나지 않는다. 맵은 112개 전부 생성(2.3 s), 라벨링 ≈ 37분/창고라 25개부터.
[합성 창고 생성기](합성_창고_생성기.md). B 의 ⑪ 일반화는 외부에서 받은 창고용으로 남는다.

## 2. 4단계 핵심 표 (채점은 전부 우리 시뮬, 테스트 창고 세트 고정)

| 방식 | 견적 시 시뮬 호출 | 기대 | 필요 재료 |
|---|---|---|---|
| ① 중립 θ (규칙 없음) | 0 | 기준선 | — |
| ② 전 창고 공통 θ (3단계 라벨 평균) | 0 | 낮음 | 3단계 |
| ③ 규칙 기반 θ (요약 통계 → 공식) | 0 | ? | 1단계 감도 |
| ④ 학습 모델 예측 θ (39ch → 회귀 8 + 분류 3; CNN/GNN, 베이스라인 MLP) | 추론 1회 | ? | 3단계 |
| ⑤ 하이브리드: ④로 시작 + 소량 탐색(10~20회) | 10~20 | 높음 | ③④ + 2단계 탐색기 |
| ⑥ 매 견적 전체 탐색(100회+) | 100+ | 최고 | 2단계 탐색기 |

**B-5 실측(2026-09-07, wallA·L2·평가 시드, [결과](2026-09-07_B5_θ적용_FleetSweep_결과.md) §6)**: ① 기준 ⑥(대수별 Optuna θ) +8~15 %,
②의 대수 축 대리(24대 θ를 전 대수에 고정) = ⑥과 시드 산포 안 → **창고 하나 안에서는 θ 한 벌로 충분**. 창고 간 ②는 3단계에서 확인.

읽는 법: ⑥이 예산 안에 들어오면 모델(④)은 "시간 단축·시작점 제공"으로만 가치가 있다. ④가 ③과 비슷하면 모델이 불필요하다는 결론도
유효한 결과다. 지표는 θ 오차가 아니라 **시뮬 처리량**(⑥ 대비 %, ① 대비 개선 %)과 **호출 횟수** 두 개.

추가 후보(여력 있을 때): 대리 모델((창고, θ) → 처리량 예측 후 그 위에서 탐색), 강화학습(데이터 효율 낮아 비교 대상으로만).

## 2-A. ④ 학습 모델 실험 — AI팀 본업 (3단계 데이터셋 위에서)

입력 = `build_input.py`의 (39, H, W) 텐서 + 운영조건 9 (명세 §8·§9 정규화 완료). 출력 = θ 연속 8(회귀) + 범주 3(분류).
손실 = 회귀(Huber/MSE, 계약 범위로 스케일) + 분류(CE) 가중합. 데이터 분할은 **창고 단위**(같은 창고의 조건들이 학습·검증에 갈리면 누수).

### 모델 후보 (단순 → 복잡, 전부 같은 분할·같은 지표)

| # | 모델 | 입력 처리 | 왜 넣나 |
|---|---|---|---|
| M0 | 다수결/평균 (연속 = 라벨 평균, 범주 = 최빈값) | — | 최저선. 이걸 못 이기면 나머지는 의미 없음 |
| M1 | 그래디언트 부스팅 (LightGBM/XGBoost) | 채널별 요약 통계 수십 개(통로 수·길이, 스테이션 밀도, 수요 방향 비대칭, 순환로 길이, 대수·밀도) | 표 데이터 강자. 특성 중요도가 그대로 "θ를 결정하는 창고 속성" 해석 |
| M2 | MLP | M1과 같은 요약 특성 | M1 대조군 |
| M3 | CNN 인코더 (ResNet-소형) + 전역 풀링 + 2헤드 | (39,H,W) 직접 | 명세가 상정한 기본형. 공간 패턴(통로 배치) 학습 |
| M4 | CNN + 운영조건 late-fusion | 이미지 인코더 출력 ⊕ 운영조건 9 → 헤드 | 대수·주문량이 θ에 미치는 영향을 분리해서 학습 |
| M5 | GNN (통로·교차로·스테이션 = 노드, 인접 = 엣지) | `extract_topology` 그래프 + 노드 특성(수요·길이·방향) | θ가 통로 단위 규칙이라 표현이 자연스러움. 창고 크기 무관(일반화 후보) |
| M6 | 시퀀스/트랜스포머 (통로 토큰열) | 통로 하나 = 토큰(rank·길이·수요·연결) | 통로 수가 창고마다 달라도 처리. M5 대조군 |
| M7 | 대리 모델 + 탐색 | (39ch, θ) → 처리량 예측 회귀 → 예측기 위에서 θ 최적화 | θ 직접 예측 대신 "시뮬 대체". 라벨 대신 (θ, KPI) 전 시행을 다 쓰므로 데이터 효율 높음 |

### 실험 항목

1. **지표 2층**: (a) θ 오차 — 연속 MAE(계약 범위 정규화), 범주 정확도. (b) **시뮬 처리량** — 예측 θ를 시뮬에 넣어 ⑥(전체 탐색) 대비 %, ①(중립) 대비 개선 %. (a)가 좋아도 (b)가 안 좋으면 실패 — θ 공간은 처리량에 대해 평평한 방향이 많다(1단계 감도 표가 이걸 말해 줌).
2. **어블레이션**: 채널 그룹(생김새 18 / 짐 흐름 6 / 통로 구조 15 / 운영조건 9) 하나씩 제거. "어느 입력이 θ를 결정하나" — 명세 §10이 뺀 것(실시간 혼잡)이 필요하지 않았는지도 여기서 검증.
3. **데이터 크기 곡선**: 창고 25 / 50 / 100 / 200개에서 (b) 지표. 합성 창고를 얼마나 더 만들어야 하는지 결정.
4. **범주형 처리 비교**: 분류 헤드 vs 회귀 후 반올림(명세 §11-2가 금지한 방식) — 금지 근거를 수치로.
5. **다중 조건 일관성**: 같은 창고에서 대수만 바꿀 때 θ 예측이 단조/연속적으로 변하는지(대수 ↑ → junction_penalty ↑ 같은 경향). 흔들리면 라벨 노이즈(시드 산포) 문제 → 3단계 시드 수 조정.
6. **일반화 축**: (i) 학습 미사용 합성 창고, (ii) **wallA 실제 창고** (합성으로만 학습 후), (iii) 창고 크기 외삽(학습보다 큰 창고). M5·M6이 (iii)에서 유리한지가 핵심.
7. **불확실성**: 앙상블/MC-dropout으로 예측 분산 → 분산 큰 창고는 ⑤ 하이브리드(탐색 추가)로 라우팅하는 규칙 후보.
8. **해석**: M1 특성 중요도, M3 Grad-CAM(어느 통로가 θ를 결정했나) — 발표·견적 리포트 설명용.

### 산출물

모델별 (a)(b) 표 + 어블레이션 + 데이터 크기 곡선 → 4단계 표의 ④·⑤ 행을 채운다. 코드 위치 `ai_theta/train/` (현재 비어 있음), 평가 스크립트는
우리 시뮬 계약을 호출(B와 공동).

## 3. 의존 관계

```
0(B 성능·계약) ──┬──> 1 감도 ──> 2 탐색기 ──> 3 데이터셋(-128) ──> 4 비교 ──> 5 서빙·B-5
0(A 리베이스) ───┘                              ↑
                                    B: 토폴로지 추출 일반화
```
0단계 없이는 1~3의 시뮬 예산이 성립하지 않는다(헤딩 60 s × 수만 런). 3단계는 -128(합성 창고)이 전제.
