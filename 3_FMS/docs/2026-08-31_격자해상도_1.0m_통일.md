# 설계 결정 — 격자 해상도 1.0m 통일 (2026-08-31)

## 문제

문서·코드 간 격자 해상도가 불일치했다.

| 층위 | 해상도 |
|---|---|
| 원본 맵 (map.yaml, occupancy_grid.npy) | 0.1m |
| 시뮬레이션 coarse 격자 (sim_engine, CELL_M=1.0) | 1.0m |
| **AI입출력명세서 v1 (§3-1, §7-1 등)** | **0.5m ← 불일치** |

방치하면 A트랙이 명세대로 0.5m 격자로 39채널 텐서·edge_cost를 만들었을 때
1.0m 시뮬과 shape이 안 맞아 `from_theta()` 연결 시점에 터진다.

## 결정: 1.0m로 통일

- **AI입출력명세서를 v1.1로 올리고 0.5m 기재 7곳을 1.0m로 수정** (격자 무관한
  θ 범위의 0.5는 유지). §7-1 틱 계산 예시도 재계산 (틱 0.333s, 8시간 86,400틱).
- 시뮬을 0.5m로 바꾸는 대안은 기각: 로봇 폭 0.641m가 0.5m 칸에 안 들어가
  "1로봇 = 1칸" 배타 점유 전제가 깨짐 (다중 칸 점유 모델링 필요 → 대공사).
- 원본 0.1m 맵은 그대로 두고 다운샘플 배율(K=10)만 유지.

## 후속

- A트랙에 명세 v1.1 변경 공유 필요 — θ 스키마 합의 때 함께 확인.
- 참고: 1.0m 칸에서도 로봇 길이 1.44m는 칸을 넘는다. 인접 칸 두 로봇의
  물리 간섭은 벽 부풀리기로는 안 잡히므로 Isaac V&V 항목에 포함할 것
