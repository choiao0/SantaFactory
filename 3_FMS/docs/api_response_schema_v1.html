견적 API 응답 스키마

AI(시뮬레이션) → 백엔드 · v1 초안 2026-08-31 · FMS B트랙 작성

백엔드가 run_id별로 요청한 시뮬레이션 1회에 대해 AI가 돌려주는 응답입니다. 백엔드는 AMR 대수(n)를 바꿔가며 반복 호출하고, 이 응답의 KPI를 비교해 최적 대수를 산출합니다.

응답 예시

{
  "run_id": "est_77_n3",          // 요청의 run_id 그대로 에코
  "status": "done",               // done | failed
  "error": null,                  // failed일 때만 사유 문자열

  "kpi": {
    // ── 완료도 ──
    "orders_total": 50,
    "orders_completed": 50,
    "inbound_total": 48,
    "inbound_completed": 48,

    // ── 시간 ──
    "makespan_s": 1740,
    "lead_time_mean_s": 210.5,
    "lead_time_p90_s": 402.0,
    "queue_time_mean_s": 87.3,

    // ── 처리량 ──
    "throughput_orders_per_h": 96.4,
    "throughput_tasks_per_h": 182.0,

    // ── 로봇 ──
    "amr_utilization": 0.63,
    "conflict_wait_ratio": 0.004,
    "distance_total_m": 12480,
    "charge_downtime_s": 0         // 배터리 모델 구현 전엔 항상 0
  }
}

필드 정의

필드타입의미 · 계산비고
run_idstring요청의 run_id 그대로 에코 — 백엔드가 회차 매칭에 사용
statusstringdone: 정상 완료 / failed: 시뮬 실패(교착 감지, 입력 오류 등)
errorstring?failed일 때 사유. done이면 null
kpi — 완료도
orders_totalint요청에 포함된 출고 주문 수
orders_completedint시나리오 시간 내 전 라인 배송이 끝난 주문 수total과 다르면 시간 내 처리 실패
inbound_total / inbound_completedint입고 건수 / 시간 내 완료 건수
kpi — 시간 (단위: 초)
makespan_sint시나리오 시작 → 마지막 태스크 완료까지 걸린 시간
lead_time_mean_sfloat주문 생성 → 주문 완료(전 라인 배송)의 평균
lead_time_p90_sfloat리드타임 90퍼센타일 — "10건 중 9건은 이 안에 처리"SLA 지표로 평균보다 유용
queue_time_mean_sfloat주문 생성 → 로봇 배차까지 평균 대기 (로봇 부족 신호)
kpi — 처리량
throughput_orders_per_hfloat완료 주문 수 ÷ makespan, 시간당 환산
throughput_tasks_per_hfloat완료 태스크(운반 단위) 기준 처리량. 주문당 라인 수가 가변이라 별도 제공
kpi — 로봇
amr_utilizationfloat0~1. 로봇이 임무 수행(이동·대기) 중인 시간 비율
conflict_wait_ratiofloat0~1. 임무 중 다른 로봇에 막혀 서 있던 시간 비율 (혼잡 신호 — 높으면 대수 추가 효율 하락)
distance_total_mint전 로봇 총 주행 거리(m). 배터리 소모 = 이 값 × consumption으로 백엔드에서도 검산 가능
charge_downtime_sint충전으로 임무를 못 한 총 시간배터리 모델 구현 후 유효 그 전엔 0 고정

규약

  • 명명·단위: snake_case. 단위는 필드명 접미사로 명시 — _s(초) · _m(미터) · _per_h(시간당) · ratio는 0~1 실수. 문자열로 감싼 숫자 금지.
  • 결정론: 같은 요청(같은 seed 포함)이면 항상 같은 응답. 재호출로 결과가 달라지지 않습니다.
  • 실패 처리: 시뮬 정체(교착)·입력 검증 실패 시 status=failed + error 사유. 부분 KPI는 주지 않습니다 (완주한 시뮬의 수치만 신뢰 가능).
  • 확장 예약: 주문별 상세(리드타임 목록), Isaac 재생용 궤적 파일 참조는 시연 연동 확정 시 옵션 필드로 추가 예정.
전제: 이 응답을 내는 시뮬은 모든 실험(알고리즘 벤치마크 + AI 통행규칙 θ 튜닝)이 끝난 최종 파라미터 적용판입니다. 시나리오는 하루 단위가 아니라 분 단위 축소 시나리오(입고 N분 + 출고 M분)로 돕니다 — 요청 스키마의 시간 필드 재정의는 별도 협의 항목.
