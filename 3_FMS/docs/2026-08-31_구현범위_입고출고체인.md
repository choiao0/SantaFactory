# 설계 결정 — 구현 범위: 입고라인 + 출고(렉→패킹 직행) (2026-08-31)

## 결정

sim_v2가 모델링하는 물류 흐름은 **입고라인과 출고라인(패킹까지) 두 개뿐**이다.

| 흐름 | 태스크 체인 | 비고 |
|---|---|---|
| **입고** | `inbound_buf[i] → aisle_buf[a]` (1태스크) | 검수(qc) 생략, 하차 버퍼에서 랙 입구버퍼 직행. v1에는 없던 신규 흐름 |
| **출고** | `aisle_buf[a] → packing[p]` (라인당 1태스크) | **induction·consol 제외** — 렉에서 바로 패킹으로 |

## 출고 멀티라인 — 합류 지점이 consol에서 packing으로 이동

[2026-08-31_설계결정_회전_우선순위_멀티라인.md](2026-08-31_설계결정_회전_우선순위_멀티라인.md)
§3의 "방법 1(consol AND-join)"을 **이 결정이 대체한다**:
- 주문 1건 = 통로 k곳 (k ∈ {1,2,3}), 라인마다 `aisle_buf[aᵢ] → packing[p]` 태스크.
- **packing은 주문당 1곳 고정** (같은 주문의 토트는 같은 포장대로).
- 주문 완료 = k개 태스크 전부 완료 (별도 pack 태스크 없음 — 운반 자체가 배송).
- 주문당 태스크 수 = k (기존 설계의 2k+1에서 대폭 단순화).

## 단순화로 흡수된 것 (명시적 한계)

- **빈 토트 공급(induction) 생략**: 피커가 쓸 빈 토트는 랙 통로에 항상 있다고 가정.
- **피커 작업 시간 0**: 출고 태스크는 주문 도착 즉시 배차 가능 (토트가 이미
  피킹돼 있다고 가정). 입고도 하차 즉시 운반 가능 가정.
- **검수(qc) 생략**: 입고 품질검사 무시.

## 입고 물량 생성 (파라미터, 팀 확정 필요)

- 입고 도착도 주문과 독립인 지수분포 스트림: `INBOUND_MEAN_GAP` (기본 = 주문과
  동일 50틱), 건수 `N_INBOUND` (기본 = 주문수와 동일). 통로는 무작위 균등.
- 실측 물동량 비율(입고:출고)이 정해지면 갱신할 것 — A트랙 task_profile에도 영향.

## 미사용 스테이션 — 향후 확장 요소로 보류 (삭제 아님)

맵에 좌표가 이미 있으므로, 시간이 되면 아래 순서/형태로 추가할 수 있게 남겨둔다:

| 스테이션 | 확장 시 역할 |
|---|---|
| `qc` (2곳) | 입고 체인에 검수 경유 추가: inbound_buf → qc → aisle_buf |
| `consol` (2곳) | 출고 취합 단계 복원: aisle_buf → consol → packing (멀티라인 합류를 packing에서 분리) |
| `induction` (2곳) | 빈 토트 공급 흐름: induction → aisle_buf |
| `vas` (3곳) | 부가서비스(라벨링 등) 경유: packing 전후 삽입 |
| `returns` (2곳) | 반품 흐름 (역방향 입고) |
| `handoff` (4곳) | 구역 간 인계 지점 |

## sim_v2 설계에의 영향

- v1의 3태스크 체인(induction→aisle_buf→consol→packing)은 **B-1e 벤치마크 전용
  `--flow v1compat` 모드로만 유지** (A* vs PIBT 이동계층 비교의 공정성 확보용).
- 기본 모드(`--flow main`)는 위 입고+출고 흐름. 상세: sim_v2 설계 문서 §6.
