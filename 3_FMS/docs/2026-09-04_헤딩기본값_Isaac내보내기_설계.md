iw.hub 스펙(AMR 모델 선정 image4): 48 V Li-ion, **가동 >8 h typical duty**, 230 V **자동 도크**, **기회 충전 지원**, 최고 2.2 m/s. 용량(Ah)·충전 시간·상태별 소모율은 스펙에 없다.

| 파라미터 | 기본값 | 근거 |
|---|---|---|
| `runtime_h` | 8.0 | 스펙 |
| `charge_h` | 1.5 | **가정** (48 V 산업용 AMR 관례) — Isaac/하드웨어 파트 확인 요청 |
| 소모 비율 주행 : 회전 : 유휴 | 1.0 : 1.0 : 0.25 | 가정. 주행 70 %·유휴 30 % 혼합에서 8 h가 나오게 정규화 |
| `soc_low` / `soc_go` / `soc_leave` | 20 % / 80 % / 95 % | 강제 충전 / 유휴 기회 충전 진입 / 충전 종료 |
| `n_chargers` | 6 | 옛 `charger[6]` + 대기 `charge_q[6]` 2줄 배치 재사용 |

## 3. sim_v2 Isaac 내보내기 (`SIM_EXPORT_ISAAC=1`)

### 3-1. 왜

Isaac 팀이 우리 결과를 보는 유일한 경로가 `2_Simulation/isaac_replay.py`(LsMin124, 2026-08-28)인데 내보내기는 sim_v1(A*)에만 있다. 헤딩 모델(2칸 차체·스윙 3칸·후진)이 실물 씬에서 부딪히지 않는지는 ROS 연동 전에 리플레이로 먼저 볼 수 있어야 한다(§7).

### 3-2. 포맷 — 기존 유지 + 추가 키

`isaac_replay.py`는 `robots[rid] = [[t, x, y], ...]` 3원소를 언패킹하고 yaw를 이동 방향에서 만든다. 4번째 원소를 넣으면 깨지므로 **3원소를 유지**하고 헤딩 정보는 별도 키로 싣는다.

```
trajectories.json
  dt_s: 1.0
  robots:   { rid: [[t_s, x_m, y_m], ...] }        # 기존 — 앞축 칸 중심. 정지·회전 틱도 한 점씩(리플레이 보간용)
  headings: { rid: [[t_s, yaw_rad], ...] }          # 신규 — 틱별 yaw (0=북 1=동 2=남 3=서 → rad, x축 기준 반시계)
  actions:  { rid: [[t_s, "rotate"|"reverse"|"wait"|"service"], ...] }   # 신규 — 이동 외 틱만
  tasks:    [ ... ]                                   # 기존
  model:    "heading" | "cell"                        # 신규
scene.json — sim_v1과 동일 (장애물 사각형·stations·nodes) + 충전 존 사각형 "zones"
          + (-144 추가) "grid": 1 m 격자 행 문자열 ['#' 장애물 '.' 통행 'a' 피커 통로 'z' 존], "station_cells": {name: [r, c]}
            — results/fleet_replay.html 범용 플레이어용. 추가 키라 isaac_replay.py 는 무시.
```

좌표 규약은 sim_v1과 같다: `x = (c + 0.5)·CELL_M − OFFSET_M`, `y = (r + 0.5)·CELL_M`, 크롭 기준 m, z-up. 헤딩 모델의 `pos`는 앞축 칸이므로 x, y는 **앞축 중심**이다. 리플레이 박스는 base_link(구동축) 기준인데 iw.hub 실측 앞끝→구동축 0.39 m라 차이는 0.1 m 미만 — 표시엔 충분하고, 정확히 맞추려면 Isaac 쪽에서 yaw 방향으로 −0.39 m 오프셋(리플레이 수정 시 함께 요청).

### 3-3. Isaac 파트에 요청할 것 (코드는 그쪽 소관)

1. `pose_at`에서 `headings`가 있으면 그 yaw를 쓰기(없으면 기존 이동 방향 추정) — 제자리 회전이 보이게.
2. 박스 원점을 앞축 → 구동축으로 −0.39 m 이동(선택).
3. `zones`를 바닥 패드로 표시(선택, 충전존 결정 "Isaac 씬은 존 바닥 표시 정도").

### 3-4. 구현 위치

틱 루프에서 위치 확정 직후(헤딩 `rb["pos"], rb["h"] = ...`, 칸 `rb["pos"] = p1`) 로봇별 `(t, r, c, h, action)`을 리스트에 붙인다. `SIM_EXPORT_ISAAC`이 없으면 기록하지 않는다(성능·결과 불변). 출력은 `sim_engine/isaac_export_<tag>/`(git 무시). 40주문 12대 헤딩 1회 = 수천 행, 문제 없음.

## 6. Lifelong MAPF 관점 정리 (2026-09-04 논의)

sim_v2는 구조적으로 이미 Lifelong MAPF(도착 즉시 새 목표, 연속 주문 스트림, PIBT 1틱 결정)다. "Lifelong 적용"은 새 알고리즘이 아니라 문헌 표준 4요소와의 정합이다.

| 요소 | 문헌 표준 | 우리 | 조치 |
|---|---|---|---|
| 평가 | 무한 스트림 + 고정 실행 시간 T 안의 완료 수 | 유한 주문(120)·makespan 기반 tasks/h — 워밍업·배수 구간 포함 | SimPy 단계에서 "T까지 실행"으로. θ 감도(-138) 노이즈 감소에도 유리 |
| 목표 할당 | 경로와 분리, 경로 거리 기반 | FIFO × **맨해튼** 최근접 — 헤딩 모델에서 뒤돌기 비용을 못 봄 | **후속 이슈**: `dmap_h(task["frm"])[state]` 거리로 교체 후 고부하 재측정 (캐시 있어 비용 0) |
| 유휴 처리 | 작업 지점을 막지 않는 주차 지점(well-formed) | 충전 존 + 장치 ⑤ | 현행 유지 |
| 가이던스 | 엣지 가중치 오프라인 최적화(GGO 계열, LoRR 상위 팀) | θ + A트랙 Optuna | A트랙에 문헌 전달 |

주문 형태 확인(같은 날): 로봇 1대 = 토트 1개, 주문 = 라인 k∈{1,2,3}(0.5/0.3/0.2) → 통로별 토트 1개, 각각 패킹 직행, 카운터로 합류 판정. 2026-08-31 결정 문서의 "consol AND-join"은 구현에서 패킹 직행으로 단순화됐다 — 그 문서에 정정 한 줄(레거시 정리 이슈에서). 멀티스톱 배칭(방법 2)은 여전히 보류.

## 7. ROS/Isaac 연동 순서 (2026-09-04 논의)

시뮬을 ROS로 "전환"하지 않는다. FMS 코어 = 결정 커널 `step()` + 실행 셸 2종(SimPy 하네스 / MQTT 데몬), Isaac 쪽 amr-agent(ROS 2)는 VDA 5050으로 명령을 받는다(아키텍처 §2-2·§3, Isaac 결정 §4-2 "코드는 그쪽 소관"). 2_Simulation 로드맵상 FMS 연동은 T4.
