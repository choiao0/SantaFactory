# 설계 결정 — 충전 스테이션 12개 → 충전 존 (닿으면 충전, 슬롯·레인 없음) (2026-09-03, 당일 개정)

> **개정 이력 (2026-09-03):** 처음엔 동쌍 밴드 "통과형 레인 + 슬롯 = 대수 + FIFO"로 정했고, 확정 맵(벽있음 + v5.8 장애물) 확인 후
> 북 밴드 r73 가로 스트립(35슬롯)도 검토했으나, **최종적으로 "동쪽 밴드 존 — 슬롯·레인 없음, 존 안에 있으면 충전"** 으로 단순화했다.
> 아래 §2가 확정안이고, 레인/스트립 안은 §2-B에 대안으로 남긴다.

## 1. 문제

현재 맵의 충전기는 `charger[0..5]` + `charge_q[0..5]` = **12칸**이고 로봇 홈이 여기에 1:1로 고정된다.
- 12대 초과는 `make_homes`가 "충전존 인근 여유 칸"에 임의 배치하는 편법으로 돌고 있다 (B0′ 16대 스윕이 그 상태).
  배터리 모델이 들어오면 그 여유 칸은 충전이 안 되므로 편법이 깨진다.
- 제품 목적(적정 대수 산정)상 충전기 수가 대수 상한을 미리 정해버리면 스윕의 의미가 훼손된다.
  거꾸로 "이 대수에 충전 슬롯이 몇 개 필요한가"가 산출물이어야 하고 그것이 구축비용에 들어간다.
- Isaac 실측(2026-09-02): 점로봇(칸) 모델은 로봇 간격이 0.707 m까지 좁아진다 — 칸 모델 홈 배치의 한계와 같은 계열.
- 시점: A트랙 학습 텐서(`static_map` 18ch, 충전기 채널 포함)가 아직 비어 있고 헤딩 모델 기본값 전환·B0′ 재실측이
  예정돼 있어, 지금 바꾸면 재생성·재실측 비용이 한 번으로 끝난다.

## 2. 결정 (확정안) — 동쪽 밴드 충전 존

| 항목 | 결정 |
|---|---|
| 형태 | **존(zone)**. 슬롯·레인·FIFO 없음. 로봇 몸(앞축 칸·뒤 칸) 중 한 칸이라도 존 안에 있으면 그 틱 충전 |
| 위치 (확정 맵 근사, 2026-09-03) | **c=103~108 × r=48~66** 중 free 칸 (기둥 x=104.1 → c103~105·r56~58 제외) ≈ 105칸. 동쪽 밴드↔북 밴드 연결 통로 **c99~102는 존에서 제외**(통행 전용) |
| 용량 | 이론 105/2 ≈ 52대, 기동 여유(회전 스윙·후진) 감안 실용 **~35대**. 슬롯 개수는 관리하지 않음 — 대수 상한은 "존 안에서 서로 갇히지 않는지"로 실측 |
| 복귀 | FREED(재배차 없음) → 목표 = **존 안의 빈 칸 중 현재 위치에서 가장 가까운 칸** (자리·도착 방향 자유, 헤딩 모델이 몸 겹침 방지). 매 틱 재평가 |
| 배차 후보 | 존 안 유휴(IDLE) 로봇 전부 — 기존 "최근접 배차" 그대로 |
| 이탈 | 남쪽(r47 → 남 밴드) 또는 통행 통로(c99~102 → 북 밴드). 회전·후진은 헤딩 모델 규칙대로 |
| 초기 배치 | 대수만큼 존 안에서 서로 몸이 겹치지 않게, 통로 쪽(c103)부터 채움 |
| 정의 위치 | `stations.json`에 `charge_zone: [{x0,y0,x1,y1}]` (m). **없으면 기존 charger 12개 홈으로 폴백**, `--flow=v1compat`은 항상 폴백 |
| 견적 출력 | 충전 인프라 = 존 면적(㎡). 대수별 "존 안 동시 주차 최대치"를 지표로 기록 |

왜 존으로 단순화했나: 레인/슬롯은 배치·압축·FIFO 로직과 스테이션 스키마가 필요했고, 확정 맵에서 북동 연결이 c99~102 네 칸으로
좁아져 레인 위치 재설계가 필요했다. "존 안이면 충전"은 FMS 변경이 홈 선택 함수 하나(고정 홈 → 존 내 최근접 빈 칸)로 끝나고,
배터리 모델도 "존 안 틱 = 충전"으로 붙는다. 대신 존 안 혼잡·갇힘은 헤딩 모델의 라이브니스 장치와 실측에 맡긴다 (§4).

### 2-B. 검토한 대안 (기록)

| 안 | 요지 | 보류 이유 |
|---|---|---|
| 동쪽 밴드 통과형 레인 2개 (c100·102, 남행, 9슬롯/레인 = 18) | FIFO, 압축 전진, 슬롯=대수 | 확정 맵에서 c99~102가 유일한 북쪽 연결 → 레인이 통행을 잠식. 슬롯·압축 로직 필요 |
| 북 밴드 r73 가로 스트립 (동향, 35슬롯, 동쪽 끝 이탈) | 용량 최대, 통행 5행 유지, 순환 방향 일치 | 북 밴드 전장을 주차가 차지, 스트립 관리 로직 필요. 용량이 더 필요해지면 재검토 |
| nose-to-wall 나란히 주차 | 아무 로봇이나 출발 | 이탈마다 후진 2칸 + 회전(3점 회전) — 교착 원인이던 동작 |

## 3. 확장 — 대수가 더 필요하면

존은 사각형 목록이라 stations.json에 사각형을 더 붙이면 된다. 동쪽 밴드 실용 ~35대를 넘으면 북 밴드 r73~74 띠(70×2칸)를
2번째 존으로 추가(§2-B 스트립 위치를 존으로) — 코드 변경 0. 그 이상은 맵 변경이며 그 사실 자체가 견적 출력물(충전 인프라 확장 비용).

## 5. 실행 순서

1. 맵 파트 벽있음 산출물 세트 수신 → 맵 동기화 ([맵버전_동기화_결정](2026-09-03_맵버전_동기화_결정.md) §4)
2. 존 범위 재확인 (c103~108 × r48~66 free 칸) → 이 문서·그림 확정
3. FMS: `charge_zone` 로드 → 존 내 최근접 빈 칸 복귀 → 헤딩 스모크에 존 시나리오(N대 복귀·재배차·갇힘 검사) 추가
4. `TURN_TICKS = 1` → B0′ 재실측 (존 안 정체 지표 포함) → 헤딩 모델 기본값 전환 → 성능 최적화

## 6. 다른 파트에 요청

- **맵/Isaac**: `charge_zone` 사각형 스키마 합의(m 단위, 기존 stations 규약). Isaac 씬은 존 바닥 표시(충전 패드) 정도 — 충전기 소품 12개는 제거 또는 유지 무관. 좌표 규약 "(x, y) = 구동축 중점 = 셀 중심" 그대로.
- **A트랙**: `static_map` 충전기 채널이 12점 → 존 사각형으로 바뀜(텐서 생성 전 반영).
