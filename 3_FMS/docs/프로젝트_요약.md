# Santa Factory — FMS(B트랙) 프로젝트 요약 (2026-09-13 기준)

## 1. 프로젝트가 하는 일

창고에 자율이동로봇(AMR)을 몇 대 들이면 되는지 **시뮬레이션으로 견적을 내는 플랫폼**이다.
사용자가 창고 정보(매장·랙·주문량·출고 시간대)와 AMR 기종을 넣으면, 시스템이 로봇 1~28대를 차례로 가상 창고에서 돌려 보고
"이 대수부터 하루 물량을 시간 안에 다 처리한다"는 무릎 대수와 비용, 리드타임 곡선을 돌려준다.
그 결과 중 최적 1건은 물리 시뮬레이터(NVIDIA Isaac Sim)에서 실제 크기의 로봇으로 다시 돌려 검증한다.

팀 구성: 웹(프론트·백엔드), AI(A트랙: 경로 비용 θ 탐색), FMS(B트랙: 로봇 운영 시뮬레이터·견적 워커), 물리(Isaac·로봇 드라이버).

## 2. FMS(B트랙)가 만든 것

**한 줄:** "로봇 운영 두뇌(배차·경로·충돌 회피)를 시뮬레이터로 감싼 것." 실기 통신·관제 화면은 범위 밖이다.

| 층 | 내용 | 코드 |
|---|---|---|
| 지도 | 0.1 m 창고 도면을 1 m 바둑판으로 내림. 랙·통로·버퍼·포장대·충전 존 | `3_FMS/map`, `map_loader.py` |
| 비용 | 칸 사이 간선마다 요금. θ 11개(A트랙 탐색)와 차선 규칙이 곱해짐 | `from_theta.py` |
| 이동(PIBT) | 매 틱 로봇 전부의 다음 한 칸을 우선순위로 정하고, 겹치면 밀어내기·대기. 로봇 = 앞축 칸 + 뒤 칸 2칸, 회전 중 스윙 칸 예약 | `pibt/` |
| 라이브니스 | 막히면 재계획·대기 점수 상승·정면 조우 양보 | `pibt/liveness.py`, `kernel/core.py` |
| 배차 | 주문 FIFO × 가장 가까운 노는 로봇. 같은 버퍼 주문을 토트 6개까지 합승 | `kernel/core.py` |
| 견적 워커 | RabbitMQ `sim.request`를 받아 주문 생성 → 시뮬 1회 → KPI 14키 `sim.result`. 컨테이너 2개 병렬 | `infra/worker/` |
| 주문 생성기 | Mendeley 신발 창고 분포(07시 피크 38 %)로 하루치 주문 생성, 출고 창으로 압축 — **2026-09-14 백엔드 `OutboundOrderGenerator` 로 이관**, 여기엔 프로파일·마스터 추출만 남음 | `order_gen/` (extract_*) |
| Isaac 연동 | 같은 커널을 플래너로 쓰는 `fms_core`(VDA5050·틱 배리어), 검증 요청 큐 계약 | `fms_core/`, `contracts/` |

| 항목 | 값 |

## 4. 최근 결정 (2026-09-11 ~ 13)

- **격자 1.0 m 고정**(물리 팀도 1.2 → 1.0 복귀 수용). 회전 안전은 격자 크기가 아니라 **차체가 쓸고 가는 칸을 계획 단계에서 예약하는 규칙**으로.
- 틱 1초·6시간 창 유지. 오차는 **속도 인자**로 잡는다(틱 0.1초·다중 틱 전진·로드맵 그래프 전환은 안 함).
- 배터리·충전은 견적에서 제외(코드는 OFF로 보존). 충전 존은 시작점·대기소.
- 판정 = 처리율 100 % 전제. 마감 직전 도착분 처리 정의는 백엔드와 합의 필요.
- 속도: 사용자 평균 무게 입력이 있으면 함수(`contracts/speed_model.py`), 없으면 0.9 고정. 물리 계획 속도와 같은 값.
- 물리 검증 플래너는 이식본 대신 `fms_core` 직접 사용 방향.

## 5. 발견한 결함

- **고밀도 교착:** 입고 흐름(역방향) + 차선·양보 규칙이 겹치면 후반 2시간 완료 0으로 잠김(12·24·28대 시드 1건씩). 출고 전용이면 사라지지만 결함은 남음 → 후속 이슈.
- **회전 발자국 누락:** 폭 0.80 로봇이 1 m 칸에서 돌면 앞 모서리가 이웃 칸으로 6 cm 나가는데 DES가 그 칸을 예약하지 않음 → 물리에서 충돌·실행 순환. 물리 팀이 코드로 확증. **-203에서 수정 중.**
