## 1. 맞는 것 (그대로 유지)

- **순수 결정 커널.** "시계·난수 주입, I/O 없음, 틱 스냅샷" — sim_v2가 v1compat 패리티(같은 rng 소비 순서 → 같은 결과)를 유지하는 원칙과 동일.
  SimPy 하네스(가상 시계)와 MQTT 데몬(벽시계)이 같은 `step()`을 호출하는 구조는 우리가 발표 대본에 쓴 "시계는 SimPy, 이동 결정은 1초 틱 PIBT" 하이브리드 그 자체.
- **시나리오 패키지 공유(맵·zones·분해 규칙·수요).** 8/31 맵 복사본 ≠ Isaac v5.8이 낸 사고([맵버전 동기화](2026-09-03_맵버전_동기화_결정.md))가
  정확히 이 공유가 깨진 경우. 단일 소스(`3_FMS/map`)와 대조 스크립트(`check_map_set.py`)가 이 박스의 구현이다.
- **Isaac = 상위 구성 검증 + 갭 캘리브레이션.** 첫 사례: iw.hub 실측(앞축 0.39 m·뒤 1.03 m·90° 0.76 s) → `TURN_TICKS 2→1`, 헤딩 모델 처리량 6대 +8%.
- **견적 산출 = 대수-성능 곡선 + 비용 모델.** B0″·고부하 스윕이 그 곡선의 원형(로봇 대수 × 처리량·리드타임·가동률·존 체류).

## 2. 고칠 것

### 2-1. 04 MAPF 플래너 — 박스가 sim_v1(A*) 시절 구조

그림: "MAPF 플래너 — 고정 솔버, PP + 시공간 예약(v1)", "시공간 예약 — 노드·엣지 × 시간창", "교통 관제 — 예약 해제·base 연장".
이것은 `sim_v1_tasks.py`(우선순위 계획 PP + 공간-시간 A* + vertex/edge 예약 장부)다. B트랙은 이를 **PIBT**로 교체했고 결과는:

| 비교 | 결과 | 근거 |
|---|---|---|
| A* vs PIBT (칸 모델, 40주문) | PIBT ≥ A* 전 구간 | [B1e](2026-08-31_B1e_벤치마크_결과.md) |
| 칸 PIBT vs 헤딩 PIBT (동기화 맵, 40주문) | 헤딩 6~10대 +6~9% | [B0z](2026-09-03_B0z_충전존_기준선.md) |
| 칸 vs 헤딩 (120주문·15틱, 28대) | 헤딩 **+38%** (509 vs 369 tasks/h) | [고부하](2026-09-04_고부하_무릎_판정.md) |

PIBT에는 시간창 예약 장부가 없다. 매 틱 전 로봇이 우선순위 순으로 다음 칸을 정하고 충돌은 밀어내기로 푼다. 그러므로:

- "MAPF 플래너" → **"PIBT 헤딩 모델 — 상태(칸,방향), 2칸 차체, 90° 회전·후진 액션, 거리항 = (칸,방향) 그래프 가중 다익스트라"**
- "시공간 예약(노드·엣지×시간창)" → **"다음 틱 점유 예약 — 자기 칸 + 뒤 칸 + 회전 스윙 3칸"** (시간 축 없음)
- "교통 관제(예약 해제·base 연장)" → **"라이브니스 장치 5종 — 대기 상승, 정체 재계획(+히스테리시스), 단조 우선순위, 정체 카운터 리셋, 도킹 칸 이탈 최우선"**
- 월드모델의 "예약 뷰" → "점유 뷰(현재 + 다음 틱)"

"고정 솔버 1종 픽스"라는 방침은 맞다 — 다만 그 1종이 PIBT 헤딩 모델이다. 칸 모델(점로봇)은 v1compat 패리티 검사용으로만 남는다
(헤딩 기본값 전환은 다음 작업).

### 2-2. 05 amr-agent — Pure Pursuit는 회전 충돌의 원인

그림: "Pure Pursuit 추종 · AMCL 자기위치". Pure Pursuit는 경로를 **달리면서 꺾는 아크**로 따라간다. Isaac 회전 충돌 분석
([결정 §2](2026-09-02_Isaac회전충돌_격자유지_PIBT확장_결정.md))에서 "현재 회전 스타일 = 아크 — 하드웨어 제약이 아니라 컨트롤러 선택"으로
확인했고, 격자 유지 + PIBT 확장을 택하면서 **실행 계층 요구사항 4개**를 Isaac 파트에 전달했다:

1. **스팟턴** — 90°는 제자리 회전(각속도만). PIBT가 예약한 스윙 3칸 안에서만 차체가 움직인다.
2. **앞축(구동축) 정렬** — 기준점 = 구동축 중점 = 셀 중심. 정지 위치가 셀 중심에서 벗어나면 뒤 칸 점유가 어긋난다.
3. **틱 배리어** — 한 틱 = 한 칸(1 m, 1 s). 다음 지시가 오기 전에 이전 칸 도착을 보장(빨리 가면 대기).
4. **후진 1칸** — 벽 레인 탈출용 3점 회전에 필요.

Pure Pursuit 하나로는 1·3이 성립하지 않는다. 박스를 **"셀 단위 추종 컨트롤러 — 직진 추종 + 제자리 회전 + 틱 배리어 + 후진"** 으로 바꾸고,
Pure Pursuit는 직진 구간의 횡편차 보정 정도로만 쓰는 것이 맞다. 이게 안 되면 FMS의 점유 예약과 실제 궤적이 다시 어긋나 SIL 검증이 의미를 잃는다.

### 2-3. θ(AI 유도)가 없다

AI입출력명세서의 구조: **A트랙 모델 → θ 11개(통로 방향 교대·순환 방향·교차로 벌점·스테이션 진입/이탈·주통로 가중·대기 비용) →
`from_theta()` → 통행 비용(edge_cost, wait_cost) → PIBT 거리항**. B트랙은 이 배관(B-2)을 끝냈고 A트랙은 39채널 입력 텐서(`build_input.py`,
우리 `map_loader`·`from_theta.extract_topology`를 import)를 만들었다. 그림에는 이 경로가 없다.

- 04 FMS 코어에 입력 **"통행 비용 ← θ (from_theta, 계약 `contracts/guidance_types.py` v2)"** 추가. θ 없으면 uniform(현재 기준선).
- 06 견적 엔진의 Optuna는 **대수·기종(운영 구성)** 을 탐색하고, θ는 **통행 규칙**을 학습한다 — 층이 다르다. θ 모델(A트랙)을 DES 실행 옆에
  두고 "구성 탐색 × θ 적용/미적용" 비교(B-5)가 견적 산출물의 일부가 되어야 한다. 입력 텐서 생성(`build_input`)도 시나리오 패키지에서 나온다.

### 2-4. 06 계산 예산

| 항목 | 실측 |
|---|---|
| 헤딩 모델 실행 시간 | 12대 12 s · 16대 16~33 s · **28대 57~86 s** (부하·시드에 따라) |
| 칸 모델 | 0.3~0.9 s |

Optuna 트라이얼 20 × 대수 8 × 기종 3 × 시드 3 = 1,440 런 × 60 s ≈ **24 CPU-시간**. 배치 워커 limit 2 vCPU면 12시간, 견적 1건에.
대책 순서: ① 성능 최적화(다음 작업 — 재계획 다익스트라 국소화, 사전 계산 테이블; 결과 동일성 기준 B0″·고부하 CSV) ② 대수 격자를 굵게(무릎 근처만 촘촘)
③ 시드 수는 P50까지(P10은 무릎 근처만) ④ 워커 수평 확장은 AMQP 잡 소비라 그림대로 가능하지만 t3.xlarge 4 vCPU 안에서는 의미 없음 — 배치 워커는
별도 노드 또는 GPU 서버 CPU 사용.

t3.xlarge(4 vCPU) 위에 k3s + Spring 2개 + PostgreSQL + EMQX + RabbitMQ + MinIO + FMS 코어 + 배치 워커: 메모리 16 GB는 되지만 CPU가 빡빡하다.
상시 서비스와 배치 워커의 노드 분리를 권한다.

### 2-5. 작은 것

- **커널 틱 = 1 s**(격자 1.0 m, SPEED 1.0 m/s, `DT = CELL_M / SPEED`). 그림의 "500 ms 제어 사이클"은 MQTT 데몬/VDA 5050 어댑터 층의 폴링 주기로
  표기하는 것이 맞다. 커널은 1 s마다 전 로봇의 다음 칸을 한 번 정한다(틱 배리어가 여기서 나온다).
- **충전 존 후보 목록**이 시나리오 패키지(zones.json 옆 `charge_zone`)에 들어가야 한다. 존은 격자 장애물이 아니라 좌표 목록이고, 대수에 따라
  후보를 앞에서부터 쓰는 방식([충전존 결정 §3](2026-09-03_충전존_결정.md)) → "이 대수엔 충전 면적 얼마"가 견적 산출물. 배터리 모델 = 존 안 틱 = 충전.
- **VDA 5050 어댑터**: 커널 출력이 "틱마다 로봇별 다음 칸(+방향·회전·후진 액션)"이라 order = 짧은 노드 열(horizon 수 칸)로 갱신하는 형태. 회전·후진은
  VDA 5050 action으로 매핑 필요(스팟턴은 표준 action이 아니라 협의).
- **KPI**: 대수-성능 곡선 P50·P10은 시드 반복 수에 직결(2-4). 현재 스윕은 시드 2개 평균.
- **시뮬 WMS ↔ FMS 경계**: 현재 sim_v2 안에 있는 주문 생성(지수 간격 `--order-gap`)·태스크 분해(주문 → 통로별 토트·packing 1곳)가 02 시뮬 WMS로
  나가면, sim_v2는 `biz/order`를 받는 커널이 된다. 이 분리 시점에 v1compat 패리티 검사는 "같은 주문 스트림을 주입했을 때 같은 결과"로 재정의.

## 3. B트랙이 그림에 맞춰 할 일 (우선순위)

1. 성능 최적화 — 2-4의 전제. 결과 동일성 기준 = `b0z_sweep.csv` + `load_sweep.csv`.
2. 헤딩 모델 기본값 전환(칸 모델은 v1compat 전용) — 2-1의 "고정 솔버 1종".
3. SimPy 하네스 — 커널 `step()`을 SimPy 프로세스가 1 s마다 호출, 주문 도착·서비스 완료·배터리는 SimPy 이벤트. 이때 주문 생성·분해를 커널 밖으로(2-5).
4. VDA 5050 어댑터 스펙 — 회전·후진 action 매핑, 틱 배리어. Isaac 파트와 2-2 요구사항 재확인.
5. θ 적용 스윕(B-5) — A트랙 θ 산출물 대기.

## 4. 다른 파트 확인 요청

- **Isaac/실행 계층**: 2-2 — Pure Pursuit 단독인지, 스팟턴·틱 배리어 컨트롤러가 계획에 있는지.
- **A트랙**: 2-3 — θ가 그림 어디로 들어가는지 합의(FMS 입력 + 견적 엔진 비교 축).
- **인프라**: 2-4 — 배치 워커 노드 분리, 견적 1건당 허용 시간.
- **아키텍처 그림 소유자**: 2-1 박스 명칭 교체.
- **06 견적 계산 엔진 — B트랙이 맡는다 (2026-09-04 결정).** 3_FMS/README 분담(A = θ 모델, B = PIBT·from_theta·fleet 벤치마크)에 06이 없었는데,
  구조상 DES 실행·구성 탐색·KPI 집계는 B트랙 `fleet_sweep_*` 스크립트를 AMQP 워커로 포장한 것이라 B가 맡기로 했다(Optuna는 대수×기종 격자엔
  과함 — 전수 스윕 권장). θ 공급은 A, 잡 발행·리포트·아티팩트는 백엔드([API계약 검토](2026-08-31_백엔드AI_API계약_검토.md) 합의 7항목).
  따라서 성능 최적화 목표는 "견적 1건(대수 격자 × 시드)당 허용 시간"으로 잡는다 — 백엔드와 합의 필요.
