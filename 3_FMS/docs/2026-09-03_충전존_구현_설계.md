# 충전 존 구현 설계 — main 흐름 기본값, `--fixed-homes` opt-in (2026-09-03)

> **개정 (2026-09-03 당일):** 처음엔 `--zone` opt-in 으로 넣었으나(§1 이유), 같은 날 **존을 기본값으로,
> 기존 고정 홈 12칸을 `--fixed-homes` opt-in 으로** 뒤집었다. 이로써 main 흐름의 B-1e CSV 비트 동일 원칙은
> 종료되고, 기준선은 [B0″(존 포함) 스윕](2026-09-03_B0z_충전존_기준선.md)으로 넘어간다. v1compat 패리티는 유지.

지라: S15P21A106-135. 결정: [충전존_결정](2026-09-03_충전존_결정.md) §2 (동쪽 밴드 존, 슬롯·레인 없음).
관련: [PIBT_헤딩 설계](2026-09-02_PIBT_헤딩_2칸점유_회전예약_설계.md) §7(라이브니스), [맵버전_동기화_결정](2026-09-03_맵버전_동기화_결정.md).

## 0. 요지

결정 문서 §2를 코드로 옮긴다. FMS 변경은 **"홈 선택 함수 하나"**(고정 홈 → 존 내 최근접 빈 칸)가 핵심이고,
그 주변에 초기 배치·재선택·지표·회귀 시나리오를 붙인다. main 흐름 기본값이며 `--fixed-homes`로 기존 고정 홈으로 돌아간다.

## 1. 기본값 여부 (개정 전 → 후)

처음 opt-in 으로 넣은 이유: 기본 경로 불변 원칙(`--theta`/`--heading` 없으면 v1compat 패리티·B-1e CSV 비트 동일).
존을 켜면 로봇 초기 위치가 바뀌어 B-1e CSV가 달라진다.

기본값으로 뒤집은 이유(사용자 결정, 2026-09-03): 존은 팀 확정 사양이고 고정 홈 12칸은 사라질 구성이다. 기본값을
사라질 구성에 묶어 두면 이후 모든 측정을 두 번 하게 된다. B-1e CSV는 이력(A* 비교)으로 보존하고, 새 기준선은
B0″(존 포함, TURN_TICKS=1) 스윕으로 잡는다. **v1compat 은 항상 고정 홈**(패리티 2311/186.9 유지) — 이것이
유일하게 남는 "기본 경로 불변" 검사다. `fleet_sweep_b1e.py`의 pibt_main 계열은 이제 재실행 시 값이 달라지므로
회귀 검사에서 제외한다(이력 파일 보존).

## 3. 복귀 목표 선택 규칙

FREED(재배차 없음) → TO_HOME 전이 시 1회 선택. 매 틱 재평가는 하지 않는다 — 목표가 바뀌면 `goal_t`(우선순위의
목표 경과 틱)가 리셋되어 우선순위가 매 틱 흔들리고, 함정 9(정체 카운터 우선순위 핑퐁)와 같은 진동이 난다.

후보 = 존 free 칸 − 예약 칸. **예약 칸** =
- 다른 로봇의 현재 목표 중 존 안 목표 (TO_HOME·IDLE) 와 그 **체비쇼프 거리 < 2 이웃** (도착 자세에 따른 뒤 칸 겹침 방지, 함정 12의 완화판 — 간격 3은 용량을 1/9로 줄여 기각, 간격 2는 106칸에 ~30대)
- 존 안에 몸(앞축 칸·뒤 칸)이 있는 다른 로봇의 점유 칸

후보 중 현재 위치에서 **맨해튼 최근접**(동률: 열 → 행 → 결정론). 다익스트라 거리로 고르지 않는 이유: 존은 열린
구역이라 맨해튼과 차이가 거의 없고, 후보 106개 × 40 ms(헤딩 거리장)를 배차마다 내는 비용이 크다. 선택된 목표의
거리장은 기존 `dmap/dmap_h` 캐시를 쓴다(존 106칸 × (H,W,4) float ≈ 30 MB 상한, 허용).

후보가 비면 예약 무시하고 존 free 칸 최근접(경고 카운트 `zone_degraded`). 그래도 없으면 기존 `home`으로 폴백.

**재선택**: TO_HOME 로봇의 목표 칸에 다른 로봇이 **IDLE 상태로 주차**해 있으면(밀려 들어와 그대로 쉰 경우)
목표를 다시 고른다(`zone_retargets` +1). 그 외(잠시 지나가는 로봇)는 PIBT 밀어내기·재계획에 맡긴다.

도착(pos == goal) → IDLE, `home = goal`. IDLE 로봇의 goal은 그 칸이므로 밀려나도 제자리로 돌아온다(기존과 동일).

## 4. 지표 (존 활성 시 SUMMARY에 추가 → v1compat CSV 불변)

| 키 | 정의 | 용도 |
|---|---|---|
| `zone_wait_steps` | TO_HOME 로봇이 **존 안에서** 이동하지 못한 틱 합 | 존 안 정체 (결정 §4 ①) |
| `zone_retargets` | 재선택 횟수 | 주차 충돌 빈도 |
| `zone_degraded` | 예약 무시 폴백 횟수 | 용량 한계 신호 |
| `zone_peak` | 동시에 앞축 칸이 존 안인 로봇 수 최대 | 견적 출력 "존 안 동시 주차 최대치". **B0″ 실측에서 항상 = n**(시작·종료 시 전원 존 안) — 용량이 걸리기 전엔 정보 없음, "임무 중 체류 분포"로 교체 예정 |
| `idle_moves` | IDLE/FREED 로봇이 밀려 이동한 칸 수 | 비임무 이동 (결정 §4 ⑥, `drive`·util 제외 확인) |

콘솔 [3] 줄에도 `존 대기/재선택/피크` 로 병기.

## 5. 회귀 — 스모크 시나리오 [D] (헤딩 모델)

`make_homes_zone`으로 N=20대를 존에 배치 → 목표 = 스테이션 근처 랜덤 칸(기존 [C] 샘플러, 체비쇼프 ≥ 3) →
전원 도달·겹침 0 (**존에서 빠져나오기**). 이어 그 위치를 시작으로 목표 = §3 규칙으로 고른 존 칸 →
전원 도달·겹침 0 (**존으로 들어가 주차**). 시드 42, 7. 완주 자체가 라이브니스 검사다(함정 13과 같은 성격).

엔드투엔드: `SIM_CHECK=1 SIM_NO_PLOT=1 python sim_v2_tasks.py base 12 40 42 1 --heading` 완주 + 겹침 0 (존 기본).
12대는 폴백 홈 12칸과 같은 대수라 기존 결과와 나란히 볼 수 있다. 16대(폴백에서 편법 배치였던 대수)도 1회.

## 6. 실측 (2026-09-03, 구현 직후, 8/31 맵 복사본·TURN_TICKS=1)

| 실행 | 결과 |
|---|---|
| 스모크 [D] 20대 × 시드 {42, 7} | 출발·복귀 전원 도달, 겹침 0. 복귀 116~121스텝 |
| `sim_v2 base 12 40 42 1 --heading` 존 (SIM_CHECK) | makespan 2330 (고정 홈 2333), 162 tasks/h 동일. 존 안 복귀 대기 83틱, 재선택 1회, 예약 무시 0, 동시 주차 최대 12, 비임무 밀림 78칸 |
| `sim_v2 base 16 40 42 1 --heading` 존 (SIM_CHECK) | 완주. 존 안 복귀 대기 129틱, 재선택 7회, 예약 무시 0, 동시 주차 최대 16. 폴백에서 편법 배치였던 대수가 정상 배치로 돌아감 |
| 고정 홈 경로 | v1compat 패리티 2311/186.9, `--fixed-homes` 칸 모델 6대 2797/135.1 = B-1e CSV 값 그대로 |

대수별 곡선(존 기본, 칸 vs 헤딩, B0′와 비교)은 [B0″ 스윕 문서](2026-09-03_B0z_충전존_기준선.md).

읽는 법: 12대에서 존 유무로 처리량이 같은 것은 수요 제약(40주문) 때문이지 존 효과가 아니다(함정 4). 존 지표는
B0″ 스윕(위 링크)과 맵 동기화 후 재실측에서 대수별로 읽는다. 재계획 틱이 존 있을 때 늘어난 것(2488→2955)은 존 안 진입·주차
때 밀어내기가 더 자주 재계획으로 넘어가기 때문 — 정차 방향 선호 규칙의 후보 근거.

`[WARN] 목표 칸 간격 <3인 쌍 1개 ((53,105),(55,105))`는 기존 charger 스테이션 좌표(폴백용 12칸)이며 존과 무관.
맵 세트에서 charger가 제거되면 사라진다.

## 7. 하지 않는 것

- 배터리(존 안 틱 = 충전) — 남은 작업 "서빙 3종"에서. 지금은 존 안 체류 자체를 세지 않는다.
- from_theta 토폴로지에서 존 칸 제외 — 맵 동기화 때 wallA 상수 재산출과 함께.
- 정차 방향 선호(서향) 규칙 — 결정 §4 ① "나쁘면 추가". B0″ 스윕에서 헤딩 16대 존 안 대기 144틱으로 증가 경향 확인, 맵 동기화 재실측에서도 같으면 도입.
- 맵 세트 수신 후 B0″ 재실측 — 이번 스윕은 8/31 맵 복사본 기준이라 맵 동기화 후 한 번 더 돈다.
