# 맵·충전 존

이 문서는 FMS의 격자, 공식 맵 생성·동기화, 충전 존 결정을 날짜별 기록에서 주제별로
재배열한 것이다. 현재 파일 위치와 구현 규칙을 설명하며 새 결론은 추가하지 않는다.

## 격자 1.0 m 결정

원본 맵은 0.1 m, 시뮬레이션 coarse 격자는 1.0 m였지만 초기 AI 명세에는 0.5 m가 적혀
있었다. 그대로 두면 A트랙의 39채널 텐서와 시뮬의 `edge_cost` shape가 달라진다.

| 층위 | 해상도 |
|---|---:|
| 원본 `occupancy_grid.npy` | 0.1 m |
| FMS 계획 격자 | **1.0 m** |
| 0.1 m→계획 격자 다운샘플 배율 | 10 |

0.5 m 셀은 로봇 폭 0.641 m보다 작아 한 로봇=한 칸 전제를 깨므로 기각했다. 1.0 m에서도
길이 1.44 m는 한 칸을 넘지만, 이는 셀 크기를 바꾸지 않고 이동계층의 2칸 점유로 다룬다.

## 맵 불일치와 동기화 결정

8월 31일 FMS 복사본과 Isaac이 쓰던 v5.8 원본은 서로 달랐다.

| 차이 | 위험 또는 결정 |
|---|---|
| 남·북 벽 구역 | 팀 결정대로 벽있음 유지 |
| 작업 스테이션 행 | FMS의 r40 라인 유지 |
| v5.8 파렛트 블록 값 6 | FMS 장애물에 포함 |
| 랙 길이 | v5.8처럼 양 끝 1 m 연장 |
| 기둥 | 실제 도면의 105개 유지 |
| 로더 장애물 값 | `(1,2,5,6)`으로 통일 |

FMS가 빈칸으로 보는 곳에 Isaac 물체가 있으면 경로가 물체를 통과하므로 위험하다. 반대로
Isaac에서 열린 곳을 벽있음 FMS가 막는 것은 로봇이 진입하지 않으므로 당장 무해하다.

## FMS 정답지 생성 절차

맵 파트 산출물을 기다리지 않고 두 원본을 보수적으로 합쳐 FMS 정답지를 만들었다.

1. `occupancy_grid_wall_ref.npy`를 벽있음 기준으로 읽는다.
2. v5.8에서 값 1·2·5·6 장애물인데 기준 맵이 통행이던 칸을 덮어쓴다.
3. v5.8이 통행으로 바꾼 칸은 벽있음 결정에 따라 열지 않는다.
4. `stations_wall_ref.json`에 `charge_zone.json`의 사각형을 합친다.
5. `build_fms_map.py`로 `occupancy_grid.npy`, `stations.json`, 보고서를 만든다.
6. 맵 파트 공식 세트가 오면 `check_map_set.py`로 0.1 m 장애물, 1 m 통행성, 스테이션
   키를 비교하고 차이가 0일 때 교체한다.

```bash
cd 3_FMS/map
python build_fms_map.py
python check_map_set.py ../../2_Simulation/t3_amr/warehouse/map
```

생성 결과는 0.1 m 기준 장애물 49,715칸이 추가됐고, 1 m free 칸은 10,020에서 9,333으로
줄었다. 랙 통로 행은 48~66에서 47~67로 다시 산출됐다. `map_loader.load_map()`과 A트랙
`build_input.py`는 모두 `3_FMS/map`을 단일 소스로 읽는다.

## 충전 존 결정

기존 `charger[0..5] + charge_q[0..5]` 12칸 고정 홈은 12대 초과 스윕과 배터리 견적을
제약했다. 최종 결정은 슬롯·레인·FIFO가 없는 동쪽 밴드 충전 존이다.

| 항목 | 결정 |
|---|---|
| 형태 | 로봇 몸의 한 칸이라도 존 안이면 충전되는 zone |
| 위치 | `c=103~108 × r=48~66` 중 free, 약 106칸 |
| 통행 제외 | 북쪽 연결 `c=99~102`는 존에서 제외 |
| 초기 배치 | 통로 쪽 열부터, 기존 홈과 체비쇼프 거리 ≥2 |
| 복귀 | 존 안 예약되지 않은 free 칸 중 맨해튼 최근접 |
| 도착 방향 | 자유, 헤딩 점유 규칙이 차체 겹침 방지 |
| 폴백 | 존 정의가 없거나 `--fixed-homes`, v1compat이면 기존 12홈 |
| 견적 의미 | 28대 초기 배치 상한을 현재 창고 충전 인프라 제약으로 사용 |

원본 좌표는 다음과 같다.

```json
{"charge_zone":[{"id":"east","x0":102.6,"y0":48.0,"x1":108.6,"y1":67.0}]}
```

## 검토한 대안과 위험

| 안 | 보류·기각 근거 |
|---|---|
| 동쪽 통과형 레인 2개 | 유일한 북쪽 연결 c99~102를 잠식하고 슬롯·압축 로직 필요 |
| 북 밴드 r73 스트립 | 북 밴드 전장을 주차가 차지하고 별도 관리 필요 |
| nose-to-wall | 출발마다 후진 2칸과 회전이 필요해 교착 원인 강화 |
| 2번째 북쪽 존 | 28대 너머 무릎 측정만을 위한 확장이므로 폐기; 용량 초과는 견적 제약 |
| 디포 방식 | 기준선·Isaac 표시 재작업이 따라 보류 |

존 안 갇힘 위험은 헤딩 PIBT의 밀어내기, 대기 상승, 재계획, 후진으로 측정했다. 고부하에서
존 정체가 최악 로봇-틱의 0.3% 미만이어서 정차 방향 선호 규칙은 도입하지 않았다.

## 구현 규칙

### 존 칸과 초기 배치

`zone_cells`는 `mask & free`를 열 오름차순, 행 오름차순으로 정렬한다.
`make_homes_zone`은 이미 뽑은 홈과 체비쇼프 거리 2 이상인 칸만 고르며, 부족하면 assert한다.
현재 간격-2 초기 배치 용량은 28대다.

### 복귀 목표와 예약

복귀 목표는 FREED에서 TO_HOME으로 갈 때 한 번 고른다. 매 틱 목표를 바꾸면 목표 경과 틱과
우선순위가 흔들리므로 재평가하지 않는다.

예약 칸은 다른 TO_HOME·IDLE 목표와 그 체비쇼프 거리 2 미만 이웃, 그리고 존 안 다른
로봇의 앞축·뒤 칸이다. 후보가 없으면 예약을 무시한 최근접 free 칸으로 폴백하고
`zone_degraded`를 올린다. 목표에 다른 IDLE 로봇이 주차했으면 다시 골라
`zone_retargets`를 올린다.

배터리 모드에서는 실제 도크 칸을 일반 주차 후보에서 제외한다. 초기 28대 배치 용량을
유지하려고 초기 배치에는 도크를 그대로 둘 수 있으며, 도크가 예약되면 그 위 유휴 로봇은
다른 존 칸으로 재선택한다.

## 랙 → 통로 버퍼 매핑

WMS 주문의 `rack_id`("A2")를 시뮬 픽업 지점 `aisle_buf[i]` 로 바꾸는 표 `map/rack_buffers.json` (S15P21A106-156, 생성 `map/build_rack_map.py`).

- 규칙: 랙 → 존(zone_id) → 존의 facility 좌표(x, y m) → `stations.json` aisle_buf 중 **같은 좌표**의 인덱스. 최근접 계산은 하지 않고 하나라도 안 맞으면 실패한다.
- 근거: 백엔드 시드(`db/seed/R__seed_demo.sql`)의 ZONE facility 22개 좌표가 aisle_buf 22개 좌표와 전부 일치한다(2026-09-08 확인). 백엔드는 존 위치를 그 존이 쓰는 통로 버퍼 스테이션 위치로 넣었다.
- 결과: 존 22 ↔ 버퍼 22 일대일, 랙 132개(존당 6개)는 전부 그 존의 버퍼 하나로 간다. 매장 1 = 존 1 = 버퍼 1.
- [2026-08-31 계약 검토 §3-1](2026-08-31_백엔드AI_API계약_검토.md) 의 "랙 번호 1~3 남쪽 / 4~6 북쪽 버퍼" 초안은 백엔드 좌표가 그렇게 들어오지 않아 이 데이터로 **대체**한다. 매핑은 랙 단위라 매장이 여러 존에 걸치는 마스터가 와도 표만 다시 만들면 된다.
- 입력은 `order_gen/master/santafactory_sample.json`(`extract_master.py` 산출물, facilities 포함). 백엔드 시드가 바뀌면 `extract_master.py` → `build_rack_map.py` 순으로 다시 돌린다. 로더는 `map_loader.load_rack_map()`.

## 지표 5종

| 키 | 정의 | 용도 |
|---|---|---|
| `zone_wait_steps` | TO_HOME이 존 안에서 이동하지 못한 로봇·틱 | 존 내부 정체 |
| `zone_retargets` | 복귀 목표 재선택 횟수 | 주차 충돌 빈도 |
| `zone_degraded` | 예약을 무시한 폴백 횟수 | 용량 한계 |
| `zone_occ_mean/p90` | 임무 중 존 안 앞축 로봇 수 분포 | 실제 체류·면적 견적 |
| `idle_moves` | IDLE/FREED 로봇의 밀림 이동 칸 | 비임무 이동 |

초기 `zone_peak`는 시작·종료 때 항상 로봇 수와 같아 정보가 없었으므로 체류 평균·p90으로
교체했다. 이 변경은 기존 기록의 결론이다.

## 기준선에서 확인된 값

- B0″ 16대 헤딩: 존 복귀 대기 128틱, 재선택 5회, 예약 무시 0.
- 고부하 L2 28대 헤딩: 존 체류 평균 2.4대, p90 10.5대.
- 고부하 L1 28대 헤딩: 존 체류 평균 5.9대, p90 18대.
- 28대까지 존 정체는 처리량을 제한하지 않았고, 그 위는 초기 배치 용량 때문에 측정하지 않았다.
