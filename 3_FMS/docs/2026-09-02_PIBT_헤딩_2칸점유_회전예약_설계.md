## 0. 한 문장

로봇 상태를 `(칸)` → `(칸, 방향)`으로 확장하고, 로봇이 **자기 칸 + 뒤 칸**을 차지하며,
방향 전환은 **제자리 회전 액션**(틱 소모, 스윙 칸 예약)으로만 일어나게 한다.
→ Isaac 스팟턴 실행과 1:1로 대응하는 계획이 나온다.

## 2. 상태와 유효성

```
상태 s = (r, c, h)      h ∈ {0=북, 1=동, 2=남, 3=서}  (명세 §3-2, pibt_core.DIRS)
pos(s)  = (r, c)                          앞축이 있는 칸
rear(s) = (r, c) − DIRS[h]                뒤 차체가 있는 칸
occupied(s) = {pos, rear}                 ③ 2칸 점유
valid(s) ⇔ pos, rear 모두 free            벽에 등을 대고 설 수 없다
```

목표는 **칸**이다 (도착 방향 무관): `goal` 칸에서 valid한 모든 h가 도착 상태.

## 3. 액션

| 액션 | 결과 상태 | 비용 (score 항) | 조건 |
|---|---|---|---|
| 전진 | `(r+dr, c+dc, h)` | `edge_cost[r, c, h]` | 새 pos free (새 rear = 옛 pos → 자동 free) |
| 좌/우 회전 | `(r, c, h±1)` | `turn_cost` (= TURN_TICKS × 1.0) | 새 rear free **그리고** 대각 칸 free (벽을 스윙으로 통과 불가) |
| 대기 | `(r, c, h)` | `wait_cost[r, c]` | — |
| **후진 1칸** | `(r−dr, c−dc, h)` | `edge_cost[r, c, (h+2)%4] × REVERSE_FACTOR(3.0)` | 새 rear(뒤의 뒤 칸) free |

- 180°는 90° 두 번 (액션 단순화, 스윙 규칙이 항상 3칸으로 고정됨).
- **후진은 구현 중 필수로 확인됨 (2026-09-02 실측):** 벽에 붙은 레인(충전기 열 c=108,
  동쪽 c=109 벽)에서는 벽 쪽에 뒤 칸이 필요한 방향으로 회전이 불가 → 회전만으로는
  레인에 갇혀 홈 6대가 양방향 교착(sim_v2 --heading r6, t=13571 STALL). 실제 로봇이
  주차장을 빠져나오듯 **후진 1칸 → 회전(3점 회전)** 으로 탈출한다. 비용 배율 3.0으로
  마지막 수단이 되게 한다 (폭 1 통로에서는 U턴이 불가하므로 후진으로 빠져나오는 것이 정답). Isaac 실행 요구사항에 "후진 1칸 프리미티브" 추가.
- score = 비용 + `dist[결과 상태]` — 기존 `edge + dist` 구조 그대로.

## 4. 회전 스윙 칸 (④)

`h → h'` 회전 중 뒤 차체는 `rear(h)`에서 `rear(h')`로 사분면을 쓸고 지나간다.

```
swing(r, c, h, h') = { rear(h), rear(h'), (r, c) − DIRS[h] − DIRS[h'] }
                   =   옛 뒤 칸   새 뒤 칸     그 사이 대각 칸
```

- 회전 틱 동안 로봇의 점유 = `{pos} ∪ swing` (4칸). 스윙 3칸 중 어느 하나라도
  다른 로봇의 현재·다음 칸이면 회전 불가(또는 밀어내기).
- 회전 첫 틱: step()이 후보 예약 시 스윙 칸까지 `occ_next`에 넣는다.
- 회전 둘째 틱 이후(TURN_TICKS−1틱): sim_v2가 `busy` 카운터로 stay만 허용하고
  스윙 칸을 `extra` 점유로 step()에 넘긴다 (서비스 중 고정과 같은 메커니즘).

## 5. 거리항 — (칸, 방향) 그래프 위 가중 다익스트라

`dist_map_h(free, goal, edge_cost, turn_cost) → (H, W, 4)`. 목표 칸의 유효 상태 전부를
0으로 두고 역방향 완화:

```
dist[(r,c,h)] = min( edge_cost[r,c,h] + dist[(r+dr, c+dc, h)],        전진 (결과 valid)
                     turn_cost       + dist[(r,c,h')]  for h'=h±1,      회전 (대각·새 rear free)
                   )
```

- ①과 같은 원리로 score가 정합 → 회전 포함 어떤 비용에서도 전진/회전이 대기를 이긴다.
- 크기 H×W×4 ≈ 5만 상태, 목표별 캐시 유지. θ·맵 고정이면 무효화 불필요.
- 좁은 통로(폭 1)에서는 회전 상태가 invalid → 거리항이 자동으로 "방까지 나가서 돌아오는" 경로를 준다.

## 6. PIBT 충돌 규칙 (다중 칸)

기존 `_PIBTStep`의 칸 하나 → **칸 집합**으로 일반화:

| 항목 | 기존 | 확장 |
|---|---|---|
| `occ_now` | `pos → agent` | `occupied(s) ∪ extra → agent` (모든 점유 칸) |
| 후보 예약 | `cand` 1칸 | `next_cells = occupied(s') ∪ (swing if 회전)` 전부 `occ_next`에 |
| 예약 충돌 | `cand in occ_next` | `next_cells ∩ occ_next(타 agent) ≠ ∅` |
| 밀어내기 | `occ_now[cand]` 1명 | `next_cells`의 점유자 **전원**(자기 제외, 미결정) 순차 resolve. 하나라도 실패 → 롤백·다음 후보 |
| 스왑 금지 | `cand == positions[parent]` | `next_cells ∩ occupied(parent 현재) ≠ ∅` |

- 밀어낸 상대가 성공 후 내가 다음 상대에서 실패하면 앞선 상대는 이미 이동 확정 —
  원 논문과 같은 성질(불필요한 이동은 허용, 충돌은 없음).
- 컨보이 추종: 뒤 로봇의 앞축이 앞 로봇이 **막 비운 뒤 칸**으로 들어감 — 물리 간격
  ≈ 0.38 m 유지 (1.44 m 차체 기준 겹침 없음).

**대기 상승 (liveness, 2026-09-02 실측 후 추가):** 뒤차가 앞차의 뒤 칸을 원하면 앞차는
회전도 못 한다(스윙에 그 칸 포함) → 밀어내기가 연쇄 실패. 이때 각 로봇의 최선 후보는 항상
"대기"(`d+1`)라 회전(`d+4`)·후진(`d+4`)을 아무도 택하지 않아 매듭이 영구화된다
(실맵 30대 스트레스에서 13대가 500틱+ 정지, sim_v2 6대도 inbound 열에서 정체).
원 PIBT는 옆 칸 하나만 비면 밀리지만 2칸 차체+스윙 3칸은 밀집에서 그게 안 된다.
→ 연속 대기가 `WAIT_ESC_GRACE`(5틱, 서비스 대기 4틱보다 길게)를 넘으면 대기 점수에
`WAIT_ESC_RATE`(1.0)/틱을 가산(상한 20). 정체 시에만 작동하며 θ의 `wait_cost`와는
독립인 시뮬 상수. `pibt_core.wait_bias()`. 정체 카운터는 "상태 변화 없음"이 아니라
**"거리 개선 없음"**(`Stagnation`) — 회전↔되돌림 진동도 정체로 잡힌다.

**정체 재계획 (liveness 2, 2026-09-02 실측 후 추가):** dist는 다른 로봇을 모른다. 벽을 보고
도킹한 로봇이 사방이 막히거나 목표에 주차한 로봇의 뒤가 벽이면 밀어내기가 불가한데 dist는
계속 "그 칸으로 가라"고 해 로봇이 회전↔되돌림을 반복했다(sim_v2 6대 packing 앞, 스모크 3대).
→ 정체가 `REPLAN_AFTER`(8틱)를 넘으면 주변(체비쇼프 반경 `REPLAN_RADIUS`=3) 로봇 점유
칸을 임시 장애물로 넣고 거리장을 재계산(`ReplanCache`, (목표, 막힌 칸) 키 캐시)해 실제
우회로를 준다. 우회로가 없으면 원래 dist로 대기. 정체 시에만 비용 발생(목표당 ~0.02 s).
**히스테리시스** (`REPLAN_HOLD`=6틱, `Replanner`): 재계획 거리장을 매 틱 다시 만들면 직각으로
맞물린 두 로봇이 서로를 장애물로 **동시에** 재계획해 동시 회전 → 상대가 바뀌어 동시 되돌림 →
주기 4틱 대칭 진동이 된다(B0′ 스윕 r8 seed 7, 트레이스로 실측). 한번 만든 우회 거리장을
6틱 유지하면 한쪽은 계획대로 밀고 나가며 상대를 밀어내고 다른 쪽은 우회 → 양립. 부수 효과로
재계산이 줄어 틱당 시간이 50~100 ms → 14~32 ms.

## 7. sim_v2 통합

- `--heading` 플래그 (기본 off). **off면 기존 경로 비트 단위 불변** (v1compat·B-1e 보존, ①과 같은 원칙).
- 로봇 초기 방향: 홈 칸에서 valid하고 타 로봇 점유와 겹치지 않는 첫 h (결정론적). 없으면 assert.
- 서비스 중 / 회전 busy: `staymap_h` (해당 상태만 0) + busy면 `extra = swing`.
- 회전 시작 감지: step 결과가 같은 pos·다른 h → `busy = TURN_TICKS − 1`, `swing` 저장.
- 지표: `turns`(회전 횟수)에 더해 **`rot`(회전 소모 틱)**, `rev`(후진 칸), `replan`(재계획 틱), `turns_idle`(비임무 회전) 추가. SUMMARY의 헤딩 키(`heading, rot_steps, rev_steps, replan_steps`)는 `--heading`일 때만 출력(기본 경로 CSV 불변). makespan은 회전 틱만큼 늘어난다 — 회전 문서(2026-08-31)가 예고한 "Isaac 실측 후 보정"이 이것.
- 우선순위: 계급(RANK) → **현재 목표를 받은 뒤 경과 틱**(단조 증가, 원 PIBT) → id. 정체 카운터(`Stagnation`)로 매기면 밀린 쪽이 다음 틱 우선권을 얻어 정면 핑퐁 진동이 된다(실측) — 정체 카운터는 대기 상승·재계획 트리거에만 쓴다.
- 정체 카운터 리셋 규칙: 거리 개선 시, 또는 **2틱 연속 목표에 머물 때**. 도착 즉시 리셋하면 목표↔옆 칸 핑퐁(0,3,0,3…)이 매번 리셋돼 재계획이 영영 안 걸리고, 리셋을 안 하면 홈 로봇이 bias 누적으로 제자리 회전을 반복한다(둘 다 실측).
- 목표(도킹) 칸 간격 점검: 목표 칸 쌍의 체비쇼프 거리 < 3이면 도착 자세에 따라 차체가 겹칠 수 있어 경고 출력. **도킹점은 로봇 길이 이상 떨어져야 한다는 물리 제약**이 격자 모델에서 이렇게 나타난다 (스모크 랜덤 목표에서 실측: 목표 칸이 이웃 주차 차체 안 → 영구 핑퐁).
- `SIM_CHECK=1`: 전 로봇 점유 집합(스윙 포함) 쌍별 disjoint + 스왑 검사.
- 히트맵/dirflow: 전진만 집계 (방향 = h).
