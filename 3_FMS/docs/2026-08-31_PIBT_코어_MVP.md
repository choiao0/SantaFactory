# PIBT 코어 MVP — 구현·버그·검증 (2026-08-31)

이슈: S15P21A106-107 (이슈명: "PIBT 코어 알고리즘 구현 및 충돌 해소 검증 (MVP)")

## 접근 방식

기존 이벤트 루프에 바로 통합하지 않고 **PIBT 코어를 독립 모듈(`pibt_core.py`)로 분리**해서
먼저 검증했다. 이유: `drive()`가 "도착시각을 미리 반환한다"는 계약에 dispatch/staging
로직 전체가 의존하는데, PIBT는 틱 단위로만 움직여 이 계약이 안 맞는다. 알고리즘 버그와
인터페이스 버그를 동시에 디버깅하지 않기 위해 분리 (핸드오프 §2 B-1c 주의사항).

## 발견한 버그 — "최종 위치만 검사하면 통과로 위장된다"

첫 구현은 좁은 통로 정면충돌 시나리오에서 두 로봇이 **같은 칸에 겹쳤다가 서로를 통과**했는데,
데모 assert가 최종 도착 위치만 검사해서 "통과"로 잘못 판정됐다.

- **원인**: 충돌 검사가 현재 점유만 보고, 이번 틱에 이미 예약된 다음 칸을 안 봄.
  이동을 확정한 로봇의 목적지 칸을 다른 로봇이 또 차지할 수 있었다.
- **수정**: 원 논문(Okumura et al., IJCAI 2019) 예약 방식으로 재작성 —
  후보 칸 잠정 예약(occ_next) → 점유자에게 재귀로 밀어내기 전파 → 실패 시 예약 롤백
  (backtracking). 부모의 현재 칸은 후보 제외로 1:1 스왑 차단, 3대 이상 순환 회전은 허용.
- **교훈**: 이후 모든 검증에 **매 틱 vertex 충돌·edge 스왑·순간이동 전수 검사**를
  넣었다 (`pibt_mvp_demo.check_collisions`). 최종 상태 검사만으로는 부족하다.

## 검증 결과

### 소형 격자 (`pibt_mvp_demo.py`)
| 시나리오 | DoD | 결과 |
|---|---|---|
| 단일 에이전트 5×5 | B-1a | 8스텝 도달 |
| 폭 1칸 통로 정면충돌 | B-1c/1d | 17스텝, 한쪽이 방으로 밀려나 비켜줌, 교착 없음 |
| 동일 설정 2회 실행 | B-1b | 매 틱 완전 일치 (결정론) |

### 실제 창고 맵 (`pibt_smoke_real_map.py`, 107×116, 통로차단 ON)
| 시나리오 | 결과 |
|---|---|
| 충전존 홈 10대 → 스테이션 | 86스텝 전원 도달, 틱당 0.28ms |
| 랜덤 OD 30대 × 시드 6개 | 전부 도달, 틱당 ~1ms |
| 랜덤 OD 60대 × 시드 2개 | 전부 도달, 틱당 ~1.6ms |

60대 과밀에서도 틱당 1.6ms — A*의 고밀도 탐색 폭발 문제 없음.
