# 합성 창고 생성기 — 파라메트릭 레이아웃 + 토폴로지 동시 출력

지라 S15P21A106-139. 코드 [`map/synth_warehouse.py`](../map/synth_warehouse.py) ·
[`sim_engine/topology_spec.py`](../sim_engine/topology_spec.py). 로드맵 3단계(데이터셋)의 입력을 만든다
([θ 실험 로드맵](2026-09-04_θ_실험_로드맵_AB공동.md#1-단계)).

## 0. 요지

1. **토폴로지를 추출하지 않고 같이 낸다.** 생성기는 통로를 어디에 팠는지 자기가 아니까, 맵과 함께
   `topology.json` 을 써 넣는다. B트랙 ⑪(토폴로지 추출 일반화)을 기다리지 않고 합성 창고를 쓸 수 있다.
2. **공식 맵은 하나도 안 변한다.** 3_FMS/map 에는 `topology.json` 이 없어 wallA 상수로 떨어진다.
   기준값 3개·80행 회귀·거리장 동일성 전부 통과 (§6).
3. **wallA 를 파라미터 8개로 다시 만든다.** 링 영역 1 m 통행성 차이 0, 토폴로지 배열 차이 0 (§3).
4. **변인은 랙 기하 하나.** 데이터셋 기본 모드(`racks`)는 밴드·스테이션·충전 존을 wallA 값에 묶고
   통로 개수·중심 간격·통로 길이만 바꾼다. θ 가 통로 단위 규칙이라 이 축이 신호를 만든다 (§4).

## 1. 창고 모형 — wallA 실측에서 뽑은 8개 숫자

```
        ┌──────────────── 북 밴드 (band_n) ────────────────┐
        │ 서                                            동 │
        │ 밴  │ │ │ │  랙 블록: 랙|통로 반복 (pitch 간격) │ 밴 │
        │ 드  │ │ │ │  통로 양 끝 = 교차로(목) + aisle_buf │ 드 │
        └──────────────── 남 밴드 (band_s) ────────────────┘
                     ↑ 링(순환로가 도는 사각 띠) — 링 밖은 전부 벽
```

| 파라미터 | wallA | 뜻 |
|---|---:|---|
| `n_aisles` | 11 | 세로 통로 개수 |
| `aisle_pitch` | 6 | 통로 중심 간격 (칸) |
| `aisle_half_width` | 1 | 통로 폭 = 2·half+1 = 3 |
| `aisle_len` | 21 | 랙 구간 행 수 |
| `band_s` / `band_n` | 7 / 6 | 남·북 가로 간선 두께 |
| `band_w` / `band_e` | 12 / 10 | 서·동 연결 통로 두께 |
| `origin` | (40, 20) | 링 좌상단 |

여기서 토폴로지가 통째로 떨어진다 — 통로 행 `[40+7, 40+7+21) = [47, 68)`,
통로 중심 `20+12+3 + 6k = 35, 41, …, 95`, 남 밴드 `[40,47)`, 북 `[68,74)`, 서 `[20,32)`,
동 `[99,109)`, 교차로 목 `(46, 68)`. **공식 맵의 `from_theta` 상수와 정확히 같은 값이다.**

## 2. 왜 추출하지 않고 같이 내는가

`from_theta.extract_topology` 는 wallA 좌표 상수에 묶여 있었고, 규칙 기반 자동 추출은 실제로
짜 봤다가 이 맵에서 깨졌다 — 세로 통로 50개(기대 11), 순환로 0개
([ai_theta/data/README.md](../ai_theta/data/README.md) '설계 결정'). 임계값 문제가 아니라 규칙을 더
설계해야 하는 문제다.

그런데 **생성기에는 그 문제가 없다.** 통로를 판 좌표를 이미 들고 있다. 그래서 맵 세트에
`topology.json` 을 같이 넣고, `map_loader.load_topology_spec()` 이 읽어 `extract_topology(spec=…)` 에
넘긴다. 파일이 없으면 wallA 상수로 떨어지므로 공식 맵 경로는 건드리지 않는다.

AI 입력(`build_input.py`)과 통행 비용(`from_theta`)이 **같은 스펙을 본다**는 성질도 그대로 유지된다.
둘이 다른 토폴로지를 보면 학습이 무의미해진다는 것이 134에서 정한 원칙이다.

## 3. wallA 재현 — 어디까지 같고 무엇이 다른가

```bash
cd 3_FMS/map
python synth_warehouse.py wallA /tmp/wallA && python synth_warehouse.py check /tmp/wallA
```

```
링 40~73 × 20~108 (3026칸) — 합성만 막힘 0 / 합성만 열림 0
토폴로지 차이(링 안): v_aisle_rank 0, main_aisle 0, loop_fwd 0, junction 0
스테이션 종류 12개, 공식과 칸이 다른 것 4개: ['input[0]', 'output[1]', 'returns[0]', 'returns[1]']
[OK] 링 영역 재현 일치
```

### 규칙만으로 안 나오는 121칸 = `extra_blocks`

이상형 링과 실측 wallA 의 차이는 3026칸 중 **121칸**이고, 전부 한 방향이다 — wallA 에만 있는
구조물이고 이상형이 더 뚫려 있다. 그래서 사각형 15개로 덮으면 차이가 0이 된다.
`WALL_A_EXTRA_BLOCKS` 가 그 목록이고, 무엇인지 알아본 것은 이렇다.

| 사각형 | 정체 |
|---|---|
| r40·r72 × c21~23 | 검수(qc) 대 구조물, 남·북 |
| r40~43 × c106~108, r43 × c95~105 | 남동 모서리 벽과 출고구 옆 구조물 |
| r56~58 의 c20~21·c25~27·c31·c99 | 밴드 중간 기둥열 |
| r56~58 의 c103~105 | 충전 존 기둥 — `charge_zone.json` 메타가 "x=104.1 주변 자동 장애물"로 적어 둔 것 |
| r67~73 × c103~108 | 북동 모서리, 충전 존 위 폐쇄 구역 |
| r70~71 × c20~30 | 북서 블록 |

합성 창고는 이 목록이 비어 있다. 실측 창고의 잡동사니를 흉내 낼 근거가 없다.

### 재현하지 않는 것 — 링 밖 부속 구역

wallA 는 북쪽에 부속 구역(r74~88)이 있고 거기에 `returns` 2개와 `output[1]` 이 있다. 창고 모형에는
없으므로 그 3칸은 북 밴드 선으로 옮겨 잡는다. `input[0]` 은 남쪽 벽 r39 에 붙어 있던 것이 링 첫 행
r40 으로 한 칸 올라온다. **위 검사에서 "칸이 다른 것 4개"가 정확히 이 네 개다.**

즉 합성 wallA 는 공식 맵의 대체품이 아니다. 실측 실행은 계속 3_FMS/map 을 쓴다.

## 4. 데이터셋 모드 — 랙만 흔든다

```bash
python synth_warehouse.py racks ../map/synth --n 112
```

밴드 두께·스테이션 개수·충전 존을 wallA 값에 고정하고 세 축만 바꾼다.

| 축 | 값 | wallA |
|---|---|---:|
| 통로 개수 | 6, 8, 9, 11, 13, 14, 16 | 11 |
| 중심 간격 | 5, 6, 7, 8 | 6 |
| 통로 길이 | 17, 21, 25, 29 | 21 |

조합 **112개**가 전부이고 `--n` 개를 축이 고루 지나가게 뽑는다(같은 n 이면 항상 같은 목록,
`--seed` 를 주면 그 시드로 무작위). 이름이 곧 파라미터다 — `r13p7l25` = 통로 13·간격 7·길이 25.

**wallA 가 이 가족의 원소다.** `r11p6l21` 의 토폴로지는 공식 맵 상수와 완전히 같다
(`test_wall_a_is_a_member_of_the_family`). 합성으로 학습하고 wallA 를 "학습 미사용 실측 창고"로
평가하는 로드맵 §2-A 실험 6-(ii)에서 기하가 어긋나지 않는다는 뜻이다.

밴드까지 흔드는 `random` 모드도 있지만 데이터셋 기본은 `racks` 다. 변인을 통로 기하 하나로
좁혀야 "θ 가 창고의 무엇에 반응했나"를 읽을 수 있다. 감도 실험에서 실효 θ 3개가 전부 통로·순환로
규칙이었던 것과 같은 이유다 ([θ 감도 실험](2026-09-04_θ감도_실험.md) §0).

### 생성은 112개 전부, 라벨링은 25개부터

**두 비용을 헷갈리면 안 된다.** 창고를 *만드는* 비용은 격자 전체 112개에 **2.3 s · 97 MB** 다 —
아낄 것이 없어서 다 만들어 둔다. 비싼 것은 창고 하나의 정답 θ 를 *구하는* 비용이고(아래), 그래서
라벨링을 25개부터 시작한다. 학습 미사용 테스트 창고는 **분할 결정**이지 생성을 미룰 이유가 아니다.

```bash
python synth_warehouse.py racks synth --n 112   # 격자 전부 (2.3 s)
```

θ 탐색 워커가 합성 창고를 가리킬 수 있다 (`run_study.py --map-dir`, S15P21A106-183). 대수 상한은
그 창고의 충전 존에서 세고, `meta_*.json` 의 `condition.map_dir` 에 어느 창고에서 뽑은 θ 인지 남는다.

```bash
python infra/worker/run_study.py --study r11p6l21_r20_g15     --map-dir map/synth/r11p6l21 --robots 20 --orders 120 --seeds 42,43,44 --trials 150
```

**창고마다 대수를 바꿔야 한다.** 크기가 다른 창고에 같은 대수를 넣으면 측정된 θ 차이가 기하
때문인지 혼잡도 때문인지 갈리지 않는다 — θ 는 막힐 때 일하는 규칙이다
([θ 감도 실험](2026-09-04_θ감도_실험.md) §0). 권장 대수는 §4 의 목록 표에 있다.

라벨링 대상 25개는 `rack_variant_grid(25)` 가 고르는 부분집합이고 이름으로 고정된다
(`r6p5l17 … r16p7l29`, 축을 고루 지나감). 같은 함수가 항상 같은 목록을 돌려주므로 "무엇을 라벨했나"가
시드 없이 재현된다.

25는 축마다 3점 이상이 깔리는 최소선이고 하룻밤에 들어온다. 데이터 크기 곡선(25/50/100/…)의 첫
점이기도 하다 — 다음 점은 **맵을 더 만드는 게 아니라 이미 있는 112개 중 라벨을 더 붙이는 일**이다.

**단서**: 랙만 흔들면 창고를 결정하는 입력이 사실상 숫자 3개라, CNN·GNN(로드맵 §2-A M3~M6)이
요약 통계 + GBM(M1)을 이길 여지가 거의 없다. M1 이 이기면 실패가 아니라 4단계의 유효한 답이다 —
모델 형태를 시험하려면 밴드·스테이션까지 흔드는 `random` 모드로 2차 배치가 필요하고,
그건 4단계에서 결정할 일이다.

산출물 `3_FMS/map/synth/` 는 **저장소에 포함한다.** 디스크로는 97 MB 지만 격자가 거의 0 과 2
뿐인 uint8 이라 압축하면 0.77 MB 다 — 재생성 산출물을 gitignore 하는 관례를 여기에 적용할 만큼
무겁지 않다. 포함하는 실질적 이유는 **θ 라벨이 특정 맵 바이트에 묶이기** 때문이다. 생성기를 고친
뒤 누가 재생성하면 맵이 바뀌는데 이미 뽑아 둔 θ 는 그대로 남아 아무 에러 없이 무효가 된다.

재생성은 여전히 결정적이다(시드 없음). 저장소 사본과 같은지는 언제든 대조할 수 있다 — `racks
--n 112` 를 다른 폴더에 돌려 SHA256 을 비교하면 560개 파일이 전부 일치한다.

## 5. 맵 세트 한 벌

`map_loader.load_map(base_dir)` 이 그대로 읽는 형식이다.

| 파일 | 내용 |
|---|---|
| `occupancy_grid.npy` | 0.1 m 격자. 다운샘플하면 의도한 1 m 통행성이 **정확히** 나오게 쓴다 (§5-1) |
| `stations.json` | 스테이션 좌표(m) + `charge_zone` 키 |
| `charge_zone.json` | 충전 존 사각형(m) |
| `topology.json` | `TopologySpec` — 통로·밴드·교차로 좌표 |
| `warehouse_spec.json` | 생성 파라미터 (재생성용) |

### 5-1. 0.1 m ↔ 1 m 왕복

`load_map` 은 왼쪽을 `OX=4` 칸 패딩한 뒤 10×10 max pooling 한다. 그래서 1 m 칸 (r, c) 는 원본
행 `[10r, 10r+10)` × 열 `[10c−4, 10c+6)` 를 덮고, 서로 겹치지 않는 완전 분할이다. 막을 칸의 블록만
랙 값 2 로 채우면 원하는 통행성이 그대로 나온다. `build_set` 이 매번 다시 다운샘플해 검산한다.

### 5-2. 스테이션 배치와 차체 간격

`aisle_buf` 는 통로 양 끝 고정(북쪽은 목 한 칸 위, 남쪽은 목 그 자리 — wallA 의 r69·r46 규칙),
나머지는 밴드 한 변의 직선 위에 놓는다. **같은 (변, inset) 을 쓰는 줄들은 한 직선을 나눠 쓴다** —
각자 균등 배치하면 겹치기 때문이다.

간격 하한은 3이다. 2칸 차체가 목표 칸 간 체비쇼프 거리 3 미만이면 도착 자세에 따라 겹쳐 핑퐁
진동이 나고, `fms_kernel` 이 실행마다 그걸 경고한다. `close_station_pairs()` 가 생성 단계에서
같은 검사를 하고, `racks` 112 조합 전부 0이다.

실패로 보지 않고 세기만 하는 이유는 **공식 맵도 한 쌍 걸리기 때문**이다 —
`charge_q` (53,105)-(55,105), 기둥에 걸려 한 칸 밀린 결과다.

| `sim_engine/map_loader.py` | `load_topology_spec()` 추가. 통로차단이 스펙 좌표를 쓴다. `make_homes` 가 충전기 개수를 맵에서 읽는다 |
| `sim_engine/from_theta.py` | `extract_topology(…, spec=None)`. 기존 상수는 `WALL_A` 별칭으로 유지 |
| `sim_engine/sim_v2_tasks.py` | `--map-dir=<폴더>`. 존을 쓸 때는 고정 홈을 만들지 않는다 |
| `sim_engine/cli/report.py` | 합성 창고일 때만 SUMMARY 에 `map_dir` 키 (조건부, 기준선 불변) |
| `ai_theta/data/build_input.py` | 맵 세트의 topology.json 을 토폴로지로 쓴다 |
| `map/synth_warehouse.py` | 신규 — 생성기 |
| `ai_theta/tests/test_synth_warehouse.py` | 신규 — 25 테스트 |

`make_homes` 의 12대 초과 폴백(`_fill_extra_homes`)은 wallA 좌표 창을 그대로 뒀다. 일반화하면
`--fixed-homes` 12대 초과 기준선이 전부 바뀐다. 합성 창고는 충전 존 경로(기본값)로 돌린다.

## 8. 남은 것

- **명시 주문 모드(`--orders-file`)는 합성 창고에서 못 쓴다.** `rack_buffers.json` 이 WMS 마스터에서
  나오는데 합성 창고에는 대응 마스터가 없다. 필요해지면 랙 id 를 생성기가 같이 발급해야 한다.
- **`station_dir` 은 링 안에서도 wallA 와 다르다** (§3의 스테이션 4개 때문). `compare_with_official`
  이 그 배열만 비교에서 뺀 이유다.
- B트랙 ⑪ 토폴로지 추출 일반화는 여전히 열려 있다. 이 이슈는 그것을 **우회**했을 뿐이고,
  외부에서 받은 맵(생성기가 안 만든 창고)에는 여전히 추출기가 필요하다.
