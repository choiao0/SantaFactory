# 0. 이 문서를 왜 읽나

AI가 **무엇을 받고 무엇을 내놓는지**만 적은 문서다.
AI를 어떻게 학습시키는지, 시뮬레이터를 어떻게 만드는지는 다른 문서에 있다.

**통행 비용이 이 사슬의 유일한 조작 대상이다.** PIBT 알고리즘도, 창고 구조도, 주문도 안 바꾼다.

실제 측정값:

```

일방통행 비용 적용                처리량 910,  필요 38대
                                    +27.5%      10대 절감
```

이 문서에 나오는 모든 입력 채널과 출력 값은
**저 표의 마지막 줄을 채우기 위해** 존재한다.

# 1. AI가 하는 일

> **창고 생김새 + 짐 흐름 + 운영 조건**을 받아서
**통행 규칙 파라미터 11개(θ)**를 정해준다.
> 

AI는 로봇의 좌표나 경로를 직접 만들지 않는다.

```
받는 것 (입력)                        내놓는 것 (출력)
──────────────────────────────      ─────────────────────────
창고 생김새      18채널
짐 흐름           6채널          →     θ  파라미터 11개
통로 구조        15채널                   연속   8개 (실수)
운영 조건         9개                     범주형 3개 (정수)
──────────────────────────────      ─────────────────────────
합쳐서 (39, 세로, 가로)
```

**채널**은 창고를 1.0m 격자로 자른 지도 한 장을 뜻한다.
그런 지도 39장을 겹쳐서 AI에 넣는다.

# 2. AI를 언제 부르나

```
창고 하나 × 운영 조건 하나 = AI 한 번
```

같은 창고라도 **AMR 대수나 주문량이 다르면 다른 조건**이다.

```
창고 A + 20대 + 주문 800건   →  AI 1회
창고 A + 30대 + 주문 800건   →  AI 1회   (대수가 다르니 따로)
창고 A + 30대 + 주문 1200건  →  AI 1회   (주문량이 다르니 따로)
```

```
❌ 매 순간 부르기        ❌ 로봇마다 부르기        ✅ 창고 × 조건마다 한 번
```

로봇이 움직일 때마다 AI를 부르는 게 아니다.
**시뮬레이션 시작 전에 한 번 불러서 규칙을 정해놓고, 그 규칙으로 끝까지 돈다.**

# 3. 좌표 규칙

## 3-1. 칸 세는 법

| 항목 | 값 |
| --- | --- |
| 단위 | 미터 |
| 칸 크기 | 1.0 m |
| 원점 | 창고 **왼쪽 아래** 모서리 |
| x가 커지면 | 동쪽(오른쪽) |
| y가 커지면 | 북쪽(위) |
| 배열 첫 줄 | **남쪽(아래)** |

```python
gx = floor(가로_미터 / 1.0)
gy = floor(세로_미터 / 1.0)
```

> 화면에 그릴 때만 위아래를 뒤집는다 (`origin="lower"`).
**계산할 때는 절대 뒤집지 않는다.**
> 

## 3-2. 방향 번호 — 프로젝트 전체 고정

```python
0 = 북(N)   (0, +1)
1 = 동(E)   (+1, 0)
2 = 남(S)   (0, -1)
3 = 서(W)   (-1, 0)

반대 방향 = (방향 + 2) % 4
```

방향 번호가 들어가는 채널이 여러 개 있으니 **순서를 절대 바꾸면 안 된다.**

## 3-3. 격자는 "로봇 중심점이 갈 수 있는 칸"이다

```
창고 실제 도면
      ↓  로봇 크기(0.641 × 1.44 m) + 안전 여유(0.3 m) 만큼 벽을 부풀림
로봇 중심점이 갈 수 있는 영역
      ↓
1.0 m 격자로 자름
```

**"폭 1칸짜리 통로"는 실제 통로가 1m라는 뜻이 아니다.**
실제 통로는 3m여도, 로봇이 지나갈 수 있는 **중심선이 한 줄뿐**이면 1칸이다.

## ⚠️ 구역은 반드시 채널을 나눠서

```
❌  구역종류 = 1(보관), 2(피킹), 3(포장)   ← 한 채널에 몰아넣기 (One-Hot 아님)
✅  보관 채널, 피킹 채널, 포장 채널을 따로  ← 지금 방식 (One-Hot)
```

한 채널에 1, 2, 3으로 넣으면 **AI가 "포장(3)이 보관(1)보다 크다"** 는
있지도 않은 관계를 배운다.

## 컨베이어

# 5. 입력 2 — 짐이 어디서 어디로 가나 (6채널)

```
shape = (6, 세로, 가로)
```

| 채널 | 이름 | 설명 |
| --- | --- | --- |
| 0 | `pickup_density` | 이 칸에서 일이 시작될 확률 |
| 1 | `dropoff_density` | 이 칸이 목적지가 될 확률 |
| 2 | `demand_dir_north` | 이 칸을 **북쪽으로** 지날 짐이 얼마나 |
| 3 | `demand_dir_east` | 동쪽으로 |
| 4 | `demand_dir_south` | 남쪽으로 |
| 5 | `demand_dir_west` | 서쪽으로 |

## 5-1. 왜 방향별 수요(2~5번)까지 필요한가

출발지와 목적지 확률만으로는 **어느 방향으로 흐르는지 알 수 없다.**

```
출발지   A 50% / B 50%
목적지   C 50% / D 50%

경우 1:  A→C,  B→D
경우 2:  A→D,  B→C
```

두 경우의 `pickup_density`, `dropoff_density`는 **완전히 똑같다.**
그런데 로봇이 실제로 흐르는 방향은 전혀 다르다.

**일방통행 방향을 북쪽으로 할지 남쪽으로 할지 정하려면
"이 통로를 어느 방향으로 지나는 짐이 많은지"를 알아야 한다.**
그게 2~5번 채널이다.

## 5-2. 만드는 방법 — 시뮬레이션 없이 계산

```python
for 주문 in 주문분포:
    경로 = 최단경로(격자, 주문.출발, 주문.도착)     # 비용 없이 그냥 최단
    for 현재칸, 다음칸 in 경로:
        방향 = 방향구하기(현재칸, 다음칸)
        demand_dir[방향, 현재칸.y, 현재칸.x] += 주문.확률

demand_dir /= demand_dir.sum()      # 전체 합이 1이 되게
```

- 최단경로가 여러 개면 **항상 같은 방식으로** 하나를 고른다 (규칙 고정)
- 모든 창고에서 **똑같은 방법**으로 만든다
- **주문 정보만으로 계산한다. 시뮬레이션을 돌리지 않는다**

# 6. 입력 3 — 통로 구조 (15채널)

```
shape = (15, 세로, 가로)
```

| 채널 | 내용 | 설명 |
| --- | --- | --- |
| 0 | 세로 통로 | 남북으로 뻗은 통로 |
| 1 | 가로 통로 | 동서로 뻗은 통로 |
| 2 | 통로 번호 (0~1로 환산) | 왼쪽부터 몇 번째 통로인지 |
| 3 | 순환로 | 외곽을 한 바퀴 도는 길 |
| 4~7 | 순환로 시계방향 (북/동/남/서) | 시계 방향으로 돌면 어느 쪽인지 |
| 8~11 | 작업자리 진입 방향 (북/동/남/서) | 작업 자리에 어느 쪽에서 들어가는지 |
| 12 | `rank_mod2` | **통로 번호가 짝수냐 홀수냐** |
| 13 | `rank_mod3_a` | 3으로 나눈 나머지가 1이냐 |
| 14 | `rank_mod3_b` | 3으로 나눈 나머지가 2이냐 |

## 6-1. 왜 통로 번호가 필요한가

AI가 **"두 통로마다 방향을 뒤집어라"** 라는 답을 내놓는다고 하자.
그런데 시스템이 **어느 게 1번 통로이고 어느 게 2번인지 모르면** 그 답을 쓸 수 없다.

## 6-2. ⚠️ 12~14번이 왜 따로 있나

2번 채널(통로 번호)은 0~1 사이로 환산돼 있다.

```
통로가  4개면  →  0,  0.33,  0.67,  1.0
통로가 12개면  →  0,  0.09,  0.18,  0.27, …
```

**이 숫자에서 "짝수 번째 통로"를 알아내기가 매우 어렵다.**
창고마다 통로 개수가 달라서 기준이 계속 바뀌기 때문이다.

그래서 **"짝수냐 홀수냐"를 아예 따로 알려준다.** 그게 12~14번 채널이다.

## 6-3. ⚠️ 통로·순환로를 사람이 손으로 정하면 안 된다

순환로 위치와 작업자리 진입 방향은 창고 그림만 봐서는 자동으로 안 나온다.
**여기서 사람이 손으로 "이쪽이 순환로다" 하고 찍으면,
통행 규칙의 절반을 이미 사람이 정해버린 것이 된다.** 새 창고에 못 쓴다.

아래 규칙을 **코드로 만들어서 모든 창고에 똑같이 적용한다.**

| 항목 | 규칙 |
| --- | --- |
| 통로 방향 | 셀이 세로로 이어지면 세로 통로, 가로로 이어지면 가로 통로 |
| 통로 묶기 | 같은 방향·같은 줄로 이어진 통로 칸을 하나로 묶고 번호 부여 |
| **통로 번호** | **세로 통로: 서쪽부터 0, 1, 2, …**<br>**가로 통로: 남쪽부터 0, 1, 2, …** |
| 순환로 | **큰 통로들로 만들어지는 가장 바깥쪽 한 바퀴** |
| 순환 방향 | 그 길을 **시계 방향**으로 돌 때의 방향 |
| 작업자리 진입 | 작업 자리에서 **가장 가까운 큰 통로 쪽** 방향 |

순환로가 없는 창고면 순환로 채널을 전부 0으로 둔다.

## 6-4. 통로 구조 원본 데이터

격자 말고, 통행 비용을 만들 때 쓸 원본 정보도 같이 넘긴다.

```python
@dataclass
class GuidanceTopology:
    aisle_id:          # 통로 고유 번호 (통로 아니면 -1)
    aisle_axis:        # 0 없음 / 1 세로 / 2 가로
    aisle_rank:        # 몇 번째 통로인지
    loop_mask:         # 순환로인지 아닌지
    loop_cw_dir:       # 시계 방향 (순환로 아니면 -1)
    station_entry_dir: # 작업자리 진입 방향 (없으면 -1)
```

| 번호 | 이름 | 예시 | 설명 |
| --- | --- | --- | --- |
| 0 | `n_agents` | 30 | AMR 몇 대 |
| 1 | `order_rate` | 800 | 하루 주문 몇 건 |
| 2 | `robot_density` | 0.015 | 얼마나 빽빽한지 (대수 ÷ 갈 수 있는 칸 수) |
| 3 | `free_ratio` | 0.63 | 창고 바닥 중 갈 수 있는 비율 |
| 4 | `map_aspect_ratio` | 1.5 | 가로 ÷ 세로 |
| 5 | `amr_speed_loaded` | 1.0 | **적재 시** 운영 속도 (m/s) |
| 6 | `amr_speed_empty` | 1.5 | **공차 시** 운영 속도 (m/s) |
| 7 | `amr_width` | 0.641 | 로봇 폭 (m) |
| 8 | `amr_length` | 1.44 | 로봇 길이 (m) |

## 7-1. 속도를 적재/공차 둘로 나눈 이유

```
벤더 정격 최대     2.2 m/s      ← 최대치일 뿐, 운영 속도가 아님
적재 운영          1.0 m/s      짐을 싣고 있을 때
공차 운영          1.5 m/s      빈 몸으로 픽업하러 갈 때
```

빈 로봇이 더 빠르므로, 왕복 시간이 짐 유무에 따라 달라진다.

### ⚠️ V1에서는 두 값을 **같게** 넣는다

```python
# V1
amr_speed_loaded = 1.0
amr_speed_empty  = 1.0     ← 같은 값

# V2 (나중에)
amr_speed_loaded = 1.0
amr_speed_empty  = 1.5
```

**필드만 미리 만들어두고 값은 나중에 채운다.** 지금 스키마를 9로 잡아두면
나중에 데이터를 다시 만들 필요가 없다.

이유는 PIBT 구조에 있다. PIBT는 **매 틱마다 전 로봇이 정확히 한 칸씩** 움직이는
동기 알고리즘이라, 속도가 다른 로봇이 섞이려면 틱을 잘게 쪼개야 한다.

```
칸 1.0 m,  비율 1.0 : 1.5

정수 틱으로 맞추려면   적재 3틱/칸,  공차 2틱/칸
틱 길이               1.0 / (2 × 1.5) = 0.333초
8시간                 86,400틱       ← 틱 1.0초(28,800틱) 대비 3배
```

**시뮬 1회가 3배 느려지고 BO 예산도 3배가 된다.**
V1은 단일 속도(보수적으로 **적재 속도**)로 가고, 속도 구분은 V2로 미룬다.

> **비교에는 영향이 없다.** B0·B1·B2 모두 같은 속도 가정을 쓰므로
순위와 개선율은 그대로다. 절대 처리량만 보수적으로 나온다.
> 

## 왜 대수(0번)와 밀도(2번)를 둘 다 주나

**같은 20대라도 작은 창고면 꽉 차고, 큰 창고면 텅 빈다.**
대수만 주면 AI가 이 차이를 모른다.

그리고 **몇 대냐에 따라 규칙 세기가 달라져야 한다.**
로봇이 적으면 일방통행이 오히려 손해(멀리 돌기만 함)고,
많으면 이득(정면충돌 제거)이다.

# 10. 일부러 안 넣는 것

| 안 넣는 것 | 이유 |
| --- | --- |
| **지금 그 칸에 로봇이 있나** | PIBT는 **막고 있는 로봇을 밀어내는 게 특기**다. "로봇 있으면 비싸다"를 가르치면 밀기를 안 하게 되고, 그냥 기다리는 멍청한 플래너가 된다 |
| **다음 순간 누가 예약했나** | 위와 같음. 충돌 처리는 PIBT 담당 |
| **로봇 각각의 위치** | 통행 규칙은 전체 공통이다. 로봇마다 다른 규칙을 주는 게 아니다 |
| **배터리 잔량** | "충전 갈까 말까"는 배차 담당이 정한다. 통행 규칙은 "충전 가기로 했으면 어느 길로"만 담당 |
| **적재 상태** | 위와 같음 |
| **실시간 혼잡도** | 아래 참고 |

## 10-1. ⚠️ 실시간 혼잡도를 안 넣는 이유 — 중요

**예상 흐름**과 **실제 혼잡**은 비슷해 보이지만 결정적으로 다르다.

|  | 예상 흐름 (`demand_dir`) | 실제 혼잡 (`traffic`) |
| --- | --- | --- |
| 언제 알 수 있나 | **시뮬 돌리기 전** | 시뮬 돌린 후 |
| 어디서 나오나 | 주문 정보 + 최단경로 계산 | 로봇이 실제로 지나간 기록 |
| 입력에 넣나 | ✅ | ❌ |

실제 혼잡도를 입력으로 받으면 이렇게 된다.

```
새 창고  →  시뮬 먼저 돌리기  →  그다음 AI
```

**이러면 "새 창고에 시뮬 없이 바로 규칙 적용"이라는 목적이 무너진다.**

> 실제 혼잡도는 **측정해서 저장은 하되 AI 입력으로는 쓰지 않는다.**
결과 분석과 나중 확장에 쓴다.

# 11. 출력 — 통행 규칙 파라미터 θ (11개)

```
연속 파라미터 8개  +  범주형 파라미터 3개
```

## 11-1. 연속 파라미터 8개 — 세기를 정하는 실수값

**모든 파라미터에 트레이드오프가 있다.** 세게 하면 좋아지는 것과 나빠지는 것이 같이 있다.

| 이름 | 쉽게 말하면 | 올리면 좋아지는 것 | 올리면 나빠지는 것 | 범위 |
| --- | --- | --- | --- | --- |
| `aisle_alt_gain` | 통로 역주행 벌금 | 정면충돌 ↓ → 대기 ↓ | 너무 세면 멀리 돌아감 | 1.0~3.5 |
| `aisle_alt_boost` | 통로 순방향 할인 | 흐름이 또렷해짐 | 너무 싸면 한 통로에 몰림 | 0.4~1.0 |
| `loop_gain` | 외곽 순환 강제 세기 | 큰 흐름 정리, 교차 감소 | 세면 지름길 포기 → 느려짐 | 1.0~3.0 |
| `main_aisle_gain` | 큰 통로 할인 | 좁은 데 몰림 방지 | 너무 싸면 큰 통로만 붐빔 | 0.5~1.2 |
| `junction_penalty` | 교차로 진입 벌금 | 교차로 정체 ↓ | 세면 교차로 피해 멀리 돎 | 1.0~3.0 |
| `station_in` | 작업자리 접근 할인 | 작업자리 도달 빨라짐 | 너무 싸면 그 앞에 줄 생김 | 0.4~1.0 |
| `station_out` | 작업자리 역방향 벌금 | 줄이 한 방향으로 정렬 | 세면 빠져나가기 어려움 | 1.0~3.0 |
| `wait_cost` | 기다리는 비용 | 높이면 안 서고 돌아감 | **너무 높으면 무리하게 밀고 들어가 데드락 ↑** | 0.5~3.0 |

## 11-2. 범주형 파라미터 3개 — 정해진 값 중 하나를 고르는 것

| 이름 | 값 | 쉽게 말하면 |
| --- | --- | --- |
| `aisle_period` | 1, 2, 3 중 하나 | 몇 통로마다 방향을 뒤집을지 |
| `aisle_phase` | 0 또는 1 | 첫 통로를 북쪽으로 할지 남쪽으로 할지 |
| `loop_dir` | 0(시계) 또는 1(반시계) | 순환 방향 |

## ⚠️ 범주형을 소수로 다루지 말 것

```
❌  1.0 ~ 3.0 사이 소수로 뽑고 반올림
✅  1, 2, 3 중에서 고르기
```

`aisle_period`는 **1이냐 2냐 3이냐**이지 1.7 같은 게 없다.
소수로 다루면 탐색도 학습도 제대로 안 된다.

AI 모델도 **"고르는 문제"로 학습**시킨다.

```
전체 손실 = 연속 8개의 회귀 오차 + 범주형 3개의 분류 오차
```

## 11-3. 저장할 때

편의상 11개를 한 줄로 저장해도 된다.

```python
[aisle_alt_gain, aisle_alt_boost, loop_gain, main_aisle_gain,
 junction_penalty, station_in, station_out, wait_cost,
 aisle_period, aisle_phase, loop_dir]
```

단 **학습할 때는 반드시 앞 8개와 뒤 3개를 나눠서** 다룬다.

## 11-4. ⚠️ "창고 전체를 북쪽 선호로" 같은 건 안 만든다

```
❌  dir_north = 0.8   (창고 전체에서 북쪽 이동을 싸게)
```

**로봇은 왕복한다.** 픽업하러 북쪽으로 갔다가 작업자리로 남쪽으로 돌아온다.
북쪽·남쪽 이동량이 거의 같으니 **전체에 같은 편향을 걸면 그냥 상쇄된다.**

효과를 내는 건 **순환**이다.

```
통로 0 → 북쪽 선호
통로 1 → 남쪽 선호      ← 번갈아 배치
통로 2 → 북쪽 선호
```

이 패턴이 실측에서 **처리량 +27.5%** 를 냈다.
`aisle_period`, `aisle_phase`, `aisle_alt_*` 가 바로 이 구조를 만드는 파라미터다.

> **"전용"이 아니라 "선호"다.** 역방향으로 못 가게 막는 게 아니라, 비싸게 만들 뿐이다.
> 

## 11-5. "회전 벌금" 파라미터는 왜 없나

통행 비용은 **"이 칸에서 이 방향으로 나갈 때 얼마"** 형태다.
**어느 방향에서 들어왔는지는 모른다.**

회전 벌금은 "북쪽에서 들어와서 동쪽으로 나감" 같은 **한 쌍**이어야 하는데,
지금 구조로는 표현할 수 없다. 그래서 뺐다.

회전에 걸리는 실제 시간은 나중에 Isaac Sim에서 측정해서 보정한다.

# 12. θ가 어떻게 쓰이나

AI 출력은 바로 쓰이지 않고, 한 단계를 더 거쳐서 **칸별 통행 비용**이 된다.

```
θ 11개  +  격자  +  통로 구조
        ↓
통행 비용
   edge_cost (세로, 가로, 4)   방향별 비용
   wait_cost (세로, 가로)      제자리 대기 비용

   범위 0.5 ~ 5.0,   1.0이 보통,   작을수록 선호
```

통로 방향은 **통로 번호**로 결정된다.

```python
그룹 = (통로번호 // aisle_period + aisle_phase) % 2

# 세로 통로:  그룹 0 → 북쪽 선호,  그룹 1 → 남쪽 선호
# 가로 통로:  그룹 0 → 동쪽 선호,  그룹 1 → 서쪽 선호
```

예를 들어 `aisle_period=1, aisle_phase=0` 이면:

```
통로 0 → 북쪽 선호
통로 1 → 남쪽 선호
통로 2 → 북쪽 선호
통로 3 → 남쪽 선호
```

## ⚠️ "못 가는 곳"은 비용으로 표현하지 않는다

```python
격자.walkable[y, x] = False      # ✅ 벽·랙·기둥·컨베이어
edge_cost[y, x, :] = 999999      # ❌ 이렇게 하면 안 됨
```

```
격자     → 갈 수 있냐 없냐
통행비용 → 갈 수 있다면 어디가 더 좋냐
```

두 개를 섞으면 나중에 반드시 문제가 생긴다.

# 14. 반드시 지킬 것 18가지

1. 배열 첫 줄은 **남쪽**, `y`가 커지면 북쪽
2. 방향 번호는 **북0 동1 남2 서3**, 반대는 `(방향+2)%4`
3. 창고 생김새 = `(18, H, W)`
4. 짐 흐름 = `(6, H, W)`
5. 통로 구조 = `(15, H, W)`
6. 운영 조건 = `(9,)`
7. 합칠 때 순서는 **생김새 → 짐 흐름 → 통로 구조** = `(39, H, W)`
8. 구역은 **채널을 나눠서** (One-Hot. 숫자 하나에 몰아넣지 않기)
9. 거리·밀도 값은 **전부 정규화**
10. 방향별 수요는 **주문 정보로 미리 계산** (시뮬 결과 아님)
11. 순환로·작업자리 진입 방향은 **코드 규칙으로 자동 추출** (사람이 찍지 않기)
12. AI 호출 단위는 **창고 × 운영조건**
13. 출력은 **연속 8 + 범주형 3**
14. 범주형은 **분류 문제로** 다루기 (소수 반올림 금지)
15. 로봇 점유·예약·개별 상태는 **입력이 아님**
16. 실시간 혼잡도는 **입력이 아님** (측정은 하되)
17. 못 가는 곳은 **격자로만** 표현
18. θ의 개수나 의미가 바뀌면 **데이터 버전도 올리기**

# 부록. 용어 정리

| 용어 | 뜻 |
| --- | --- |
| **통행 비용 (Guidance)** | 칸마다 방향별로 매긴 "이 방향으로 가는 게 얼마나 비싼가" |
| **θ (세타)** | 통행 비용을 만들어내는 파라미터 11개. AI가 내놓는 것 |
| **PIBT** | 로봇들이 서로 안 부딪히게 다음 칸을 정하는 알고리즘 |
| **격자 (Grid)** | 창고를 1.0m로 자른 지도. 로봇 **중심점**이 갈 수 있는 칸 |
| **통로 번호 (Aisle Rank)** | 같은 방향 통로들에 매긴 순번. 세로는 서쪽부터, 가로는 남쪽부터 |
| **예상 흐름 (Demand)** | 주문 정보로 **미리 계산**한 방향별 물동량. AI 입력 |
| **실제 혼잡 (Traffic)** | 시뮬 돌린 후 **측정**한 통행량. AI 입력 아님 |
| **창고 × 운영조건** | AI 호출과 학습 데이터의 기본 단위 |
