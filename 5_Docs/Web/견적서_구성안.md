# 견적서(PDF) 구성안

웹 리포트 '견적' 단계의 "견적서 PDF 저장" 버튼이 만들어 낼 A4 2장 문서의 구성. 예시 이미지는 샘플 데이터로 그린 시안이고,
색·글꼴·라벨 방식은 웹 화면(`SantaFactoryFE/src/index.css`)을 그대로 따랐다.

## 문서 원칙 (2026-09-17 결정)

1. **독자는 창고 관리자.** 개발·시뮬 용어를 쓰지 않는다. 아래 표기 규칙을 따른다.
2. **충전기 항목 없음.** 비용은 로봇 본체 + 설치비만. 충전 관련 전제도 적지 않는다.
3. **입고 항목 없음.** 입고/출고를 나누지 않고 전부 "주문" 으로 쓴다.
4. **계산 조건·전제 섹션 없음.** 적용 속도·상자 수·6시간 조건 같은 시뮬 설정은 내부 정보라 문서에 싣지 않는다. 사용자에게 필요한 주의는 마지막 "유의 사항" 한 블록으로 충분하다.

| 내부 용어 | 문서 표기 |
|---|---|
| run, sweep, 스윕 | 시뮬레이션, "1대부터 28대까지 28회 시뮬레이션" |
| knee, 무릎 | "15대부터는 로봇을 늘려도 처리량이 거의 늘지 않습니다", 표 칩 "효과 정체 시작" |
| KPI, throughput | 주문 처리율 (접수한 주문 중 처리 완료 비율) |
| utilization, 가동률 | 로봇 가동률 (로봇이 실제로 일한 시간 비율) |
| lead time p90 | **주문 처리 시간 (90 % 기준)** — 라벨에 항상 "(90 % 기준)" 을 붙이고 설명은 "주문의 90 %가 이 시간 안에 처리 완료", 평균값(`lead_time_mean_s`)을 옆에 함께 적어 평균이 아님을 드러낸다. "보장" 이라는 말은 쓰지 않는다(시뮬레이션 결과). 초 → **분** |
| lead time mean | 평균 주문 처리 시간, "전체 평균" 명시 |
| queue time | 로봇 배정 대기 (주문이 로봇을 기다린 시간) |
| conflict wait ratio | 통로 혼잡으로 멈춘 시간 (운행 시간 중 비율) |
| distance total | 로봇 총 이동 거리, m → **km** |
| efficiency score | 효율 점수 = 주문 처리율 × 로봇 가동률 ÷ 100, "주문을 많이 처리하면서 로봇이 놀지 않을수록 높음" |
| AMR | 첫 등장은 로봇(iw.hub), 이후 로봇. 문서 제목만 "AMR 도입 견적서" |
| 토트 | 토트(운반 상자), 이후 상자 |
| Isaac Sim, 검증 런 | 3D 물리 시뮬레이션(Isaac Sim), "물리 검증" |
| DONE / PARTIAL / CANCELLED | 완료 / 일부 실패 / 취소 |
| 충족·미달 | 달성·미달 |
| 상태 라벨 영어(RECOMMENDED FLEET 등) | 전부 한글. 영어는 브랜드명과 견적 번호만 |

## 샘플 시나리오

판교 3PL 센터 B동, 60 × 40 m, 작업자 12명, 주문 처리 시간대 13:00~18:00, 하루 평균 주문 1,000건,
목표 주문 처리율 95 %, 목표 로봇 가동률 60 %, 예산 3억 원, 비교 범위 1~28대.
권장 14대(처리율 95.6 %, 가동률 70.2 %, 구축비 2억 1,700만 원, 주문 처리 시간 6.4분), 효과 정체 시작 15대.

숫자는 백엔드 판정 규칙(`EstimateEvaluator`)으로 검산했다.
권장 = 목표·예산을 만족하는 대수 중 효율 점수 최고 → 14~19대 중 14대.
효과 정체 = 가장 가파른 구간(1→2대, +11.1 %p) 증가분의 20 % 아래로 처음 떨어지는 대수 → 15→16대가 +0.4 %p 라 15대.
12·13대 효율 점수(69.2·68.1)가 14대(67.1)보다 높지만 처리율 미달로 빠진다. 이 설명을 표 아래 각주에 넣었다.

## 기능 흐름 (2026-09-17 결정: PDF 는 백엔드가 만든다)

견적서는 화면에 그리는 것이 아니라 **다운로드·메일 전송**용이다. 메일은 프런트만으로 못 보내므로 PDF 생성은 백엔드 몫이고,
백엔드가 자기 DB 에서 바로 읽어 그리므로 "상세 응답에 필드 추가" 는 대부분 필요 없다.

**다운로드**
1. 견적 화면 "견적서 PDF 저장" → `GET /api/estimates/{id}/quote.pdf`
2. 백엔드가 견적 · 대수별 결과(`SimScenario`) · 창고(`estimate.getWarehouse()`) · 단가(`EstimateProperties`) · 검증 결과를 읽어 문서 모델을 만든다
3. HTML 템플릿(시안 2장)에 채워 PDF 로 변환
4. `application/pdf`, `Content-Disposition: attachment; filename=EST-….pdf` 로 응답

**메일 전송**
1. "메일로 받기" → `POST /api/estimates/{id}/quote/email` (받는 주소 기본값 = 로그인 계정 이메일)
2. 즉시 202 응답, 뒤에서 위 2~3 단계로 PDF 를 만든 뒤 기존 `EmailSender`(`@Async`, `spring-boot-starter-mail`)로 첨부 발송
3. 실패는 로그 + 화면 안내 "잠시 후 다시 시도"

**공통**
- 소유자 확인은 상세 조회와 같은 규칙. 상태가 `DONE`·`PARTIAL` 일 때만 생성, `RUNNING`·`CANCELLED` 는 거절.
- 요청마다 새로 만든다(같은 견적 = 같은 문서). 필요해지면 MinIO(`io.minio` 이미 의존성 있음)에 캐시.
- 영상은 만료되는 서명 주소 대신 견적 상세 페이지 주소를 넣는다.

## 백엔드 할 일 (현재 코드 기준)

시뮬 결과 메시지의 지표 14개는 `SimulationResponse.Kpi` 가 이미 전부 받아 읽고, 저장만 4개다. 검증 결과도 계약(`SIM_VERIFY_CONTRACT.md` §3)에는
가동 로봇 수 · 종료 사유 · 경고 · 14개 지표가 실려 오는데 `VerifyResultResponse` 는 영상 키만 읽는다. 워커 · 큐 메시지 형식은 바꾸지 않는다.

**필요 없어진 것.** 창고 정보 · 단가 · 견적 번호를 상세 응답(`GET /api/estimates/{id}`)에 추가하는 일, 영상 고정 주소 엔드포인트. 웹 화면에도 같은 값을 보여 주기로 하면 그때 응답에 넣는다.

**라이브러리 결정(1번의 크기를 정한다).**
- 자바 HTML→PDF(openhtmltopdf 등): 서버 부담 작음, 폰트 번들 가능. 단 CSS 지원이 CSS 2.1 수준이라 **시안의 grid · flex 배치를 표 기반으로 다시 짜야** 하고 SVG 그래프는 플러그인 필요.
- 헤드리스 크롬(Playwright Java 등)으로 시안 HTML 을 그대로 인쇄: 모양은 시안과 동일, 대신 EC2(4코어)에 브라우저 프로세스가 올라간다. 시안 이미지도 이 방식으로 만들었다.
- 팀 결정 사항. 모양 우선이면 후자, 운영 부담 우선이면 전자.

**하지 않는 것.** 충전기 비용, 입고 필드, 계산 조건 노출, 리드타임 판정 기준 값 결정(설정 `estimate.lead-time-p90-limit` 만 채우면 켜짐), 워커 · 큐 변경.

**순서.** 4 · 5 완료 → 1 · 6 → 2 → 3.

## PDF 생성 진행 계획 — 방식 ③ 별도 변환 컨테이너 (2026-09-17 정리)

**방식 비교 결론.** 메일 첨부가 요구사항이라 브라우저 인쇄만으로는 안 되고, 자바 HTML→PDF 라이브러리는 CSS 지원이 낮아 시안의 grid·flex 배치를 표로 다시 짜야 하며,
백엔드 JVM 안에 헤드리스 크롬을 넣는 것은 EC2 t3.medium(4 GB)에 부담이다. **Gotenberg 컨테이너**(크로미움 내장, HTTP 로 HTML → PDF)를 compose 에 하나 추가하고 백엔드가 HTTP 로 호출한다.
시안 HTML 을 그대로 쓰고, 백엔드는 가벼우며, 변환기가 죽어도 PDF 기능만 멈춘다.

| 단계 | 할 일 | 바꿀 곳 | 공수 |
|---|---|---|---|
| 1 | compose 에 `pdf` 서비스(`gotenberg/gotenberg:8`). 외부 포트 없음, `mem_limit: 512m`, 동시 변환 1건. Jenkins 기동 확인에 포함 | `4_Web/docker-compose.yml`, `Jenkinsfile` | 0.5일 |
| 2 | 시안 HTML → Thymeleaf 템플릿(`spring-boot-starter-thymeleaf` 추가). 표·곡선을 JS 가 아니라 서버에서 채워 변환기에서 스크립트를 끈다. Pretendard 폰트·로고를 HTML 과 함께 multipart 로 보내 CDN 의존 제거 | `src/main/resources/templates/quote/quote.html`, `static/quote/` 폰트·로고, `QuoteDocument` 모델 | 1일 |
| 3 | `QuotePdfService`: 견적·runs·창고(`estimate.getWarehouse()`)·단가(`EstimateProperties`)·`verification` → 문서 모델(12행 선택, 초→분, `formatWon` 규칙, 견적 번호 `EST-yyyyMMdd-NNNN`) → 템플릿 → `GotenbergClient`(Spring `RestClient`, `POST /forms/chromium/convert/html`, A4 · 여백 0 · 배경 인쇄) → PDF 바이트. `GET /api/estimates/{id}/quote.pdf` 첨부 응답. 상태 DONE·PARTIAL 만, 소유자 확인은 `detail()` 과 동일, 30초 타임아웃, 세마포어 1, 변환기 장애 시 503 | `QuotePdfService`, `GotenbergClient`, `EstimateController` | 1일 |
| 4 | `EmailSender.sendWithAttachment(...)`(`MimeMessageHelper`). `POST /api/estimates/{id}/quote/email` → 202 후 `@Async` 로 생성·발송, 받는 주소 = 로그인 계정 이메일. `mail.enabled=false` 면 로그만 | `EmailSender`, `EstimateController` | 0.5일 |
| 5 | "견적서 PDF 저장" 버튼 → 다운로드 API(blob 저장), "메일로 받기" 버튼 추가, 완료 전 비활성 | `QuoteStep.jsx`, `api/estimates.js` | 0.5일 |
| 6 | 로컬 compose 로 실제 견적 1건 PDF 생성 — 한글 폰트·2쪽·용량 확인. 문서 모델 단위 테스트(행 선택·표기 변환), 컨트롤러는 변환기 목 | 테스트 | 포함 |

순서 1 → 2 → 3 → 4 → 5 (1·2 는 병행 가능). 합계 약 3.5일.

**구현 완료 (2026-09-17, 브랜치 `feature/S15P21A106-236-…`).** 1~5 전부.
- 변환기: `4_Web/pdf/Dockerfile`(Gotenberg 8 + Pretendard 가변 TTF 번들, 이미지 2.5 GB), compose `pdf` 서비스(`mem_limit 512m`, JS 비활성), 백엔드 `depends_on`. Jenkins 는 `build backend pdf`.
- 백엔드: `service/estimate/quote/` — `QuoteDocument`(템플릿 값) · `QuoteDocumentFactory`(상세 응답+창고 → 문서, 12행 선택·표기 변환·곡선 좌표) · `QuoteFormat` · `GotenbergClient`(RestClient multipart, 동시 1건, 503) · `QuotePdfService` · `QuoteMailService`(@Async, 계정 이메일) · `QuotePdfProperties`(`pdf.base-url`·`timeout`·`site-url`). 템플릿 `templates/quote/quote.html`(Thymeleaf, 스크립트 없음, 로고 base64). `EmailSender.sendWithAttachment`. 에러 코드 `EST409_2`(계산 전) · `PDF503`(변환기 없음).
- API: `GET /api/estimates/{id}/quote.pdf`(첨부 `견적서_EST-yyyyMMdd-NNNN.pdf`), `POST /api/estimates/{id}/quote/email`(202).
- 프런트: `api.download`(blob 저장 + 401 갱신 1회), `downloadQuotePdf`·`emailQuote`, `QuoteStep` 의 `QuoteActions` 버튼 2개(완료 전 비활성).
- 실측: 로컬 컨테이너에서 샘플 견적 변환 0.7 s, PDF 620 KB, 2쪽, 한글 폰트 정상. 테스트 `QuoteFormatTest`·`QuoteDocumentFactoryTest`·`QuoteTemplateTest`(렌더 결과를 `build/quote-preview.html` 에 남김)·컨트롤러 4건.
- 로컬에서 보려면: `docker compose -f 4_Web/docker-compose.yml up -d pdf` 뒤 백엔드에 `PDF_BASE_URL=http://localhost:3000`.

**위험·대응.** 변환 시 크로미움 ~300 MB → `mem_limit` + 동시 1건. 견적서 생성은 버튼을 눌렀을 때만이라 빈도가 낮다. 부족하면 변환 컨테이너만 다른 호스트로 빼고 백엔드는 주소(`pdf.base-url`)만 바꾼다.
영상 링크는 만료되는 서명 주소 대신 견적 상세 페이지 주소(`app.public-url` 설정) 를 넣는다.

**결정(2026-09-17).** ① 메일 수신자 = 로그인 계정 이메일 고정, 입력 없음. ③ 파일명 = `견적서_EST-20260917-0142.pdf`. ② 다운로드·메일 권한은 상세 조회와 같은 `OwnershipGuard.checkEstimate` 규칙(견적이 속한 창고의 소유자, ADMIN 은 전부. 남의 것은 403 이 아니라 404) — 확정 대기.
