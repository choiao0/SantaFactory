# 1. 빌드 · 배포 매뉴얼

산타팩토리는 창고·주문 조건을 받아 **AMR 도입 대수와 비용을 견적**(DES 시뮬레이션)하고, 권장 대수를 **Isaac Sim 3D 주행으로 검증**해 영상과 물리 지표를 보여 주는 웹 서비스다.

## 1-1. 시스템 구성

```
브라우저 ── HTTPS 443 ── EC2 Nginx ─┬─ /                          → frontend  (k3s 파드, ClusterIP 10.43.0.30:80)
                                    ├─ /api/ · /swagger-ui · /v3/api-docs → backend (k3s 파드, ClusterIP 10.43.0.80:8080)
                                    ├─ /media/                    → MinIO 127.0.0.1:9002 (검증 영상, 서명 URL)
                                    ├─ /jenkins/ · /sonarqube/ · /portainer/ → Jenkins 9090 · SonarQube 9000 · Portainer 9100
                                    └─ /v2/                       → 사설 레지스트리 127.0.0.1:5000 (GCP NAT IP 만, GET/HEAD)
EC2 Nginx stream 5671(TLS) → RabbitMQ 5672                         (GCP DES 워커 전용, 출발지 NAT IP 만)

backend ── PostgreSQL 5432 · Redis 6379 · RabbitMQ 5672 · MinIO (EC2 docker compose)
        └─ pdf(Gotenberg, k3s 파드)
견적:  backend ─ RabbitMQ sim.request ─▶ DES 워커 ×12 (k3s, GCP 노드 3대) ─ sim.result ─▶ backend
검증:  backend ─ RabbitMQ sim.verify.request ─▶ host-orch (EC2 compose) ─ MQTT(EMQX 1883) ─▶ GPU 러너(Isaac Sim)
       GPU 러너 ─ 영상 업로드 ─▶ MinIO ;  host-orch ─ sim.verify.result ─▶ backend
```

## 1-3. 빌드

소스를 클론한다: `git clone <SSAFY GitLab S15P21A106 저장소>` → 배포 브랜치는 `release`, 개발 통합은 `develop`.

| 대상 | 로컬 빌드 | 컨테이너 이미지 |
|---|---|---|
| 백엔드 | `cd 4_Web/SantaFactoryBE && ./gradlew clean bootJar` (JDK 21). 테스트 `./gradlew test`(Docker 필요) | `docker compose -f 4_Web/docker-compose.yml build backend` → `santafactory-be` |
| 프론트엔드 | `cd 4_Web/SantaFactoryFE && npm ci && npm run build` (API 주소 `VITE_API_BASE_URL`, 기본 `/api`). 테스트 `npm test` | `docker compose -f 4_Web/docker-compose.yml build frontend` → `santafactory-fe` |
| PDF 변환기 | — | `docker compose -f 4_Web/docker-compose.yml build pdf` → `santafactory-pdf` |
| 견적 DES 워커 | `3_FMS/sim_engine` 은 파이썬 스크립트(빌드 없음), 테스트 `python -m pytest` | `docker compose -f 3_FMS/infra/compose.estimate.yml build` → `fms-estimate-worker` |
| fms-core · host-orch | — | `compose.fms-core.yml` · `compose.host-orch.yml` 의 `build` → `fms-core` · `fms-host-orch` |
| GPU 러너 | — | 아래 명령(첫 빌드 약 25분, 이미지 약 26 GB) |

```bash
docker build -f 2_Simulation/t3_amr/deploy/Dockerfile \
    --build-context sim_engine=3_FMS/sim_engine --build-context fms_map=3_FMS/map \
    -t t3amr-runner:dev 2_Simulation/t3_amr
docker run --rm --gpus all t3amr-runner:dev check        # GPU · Isaac import · ffmpeg · 에셋 확인
```
`--build-context` 두 개를 빠뜨리면 계획기 원본·맵이 이미지에 들어가지 않아 실행 중 ImportError 가 난다.

## 1-4. 환경 변수

값은 적지 않는다. **어디에 넣는지**가 중요하다 — 운영은 Jenkins 자격증명(파일)이 배포 때 `.env` 를 만들고 배포가 끝나면 지운다.

### Jenkins

| 종류 | 이름 | 내용 |
|---|---|---|
| 전역 환경 변수 | `WEB_DEPLOY=k3s` | 웹(backend·pdf·frontend)을 k3s 로 롤링 배포. 비우면 EC2 compose |
| 전역 환경 변수 | `FMS_DEPLOY=k3s` | DES 워커를 k3s(GCP 노드)로. 비우면 EC2 compose |
| 전역 환경 변수 | `WORKER_REPLICAS=0` | EC2 compose 워커를 띄우지 않음 |
| 자격증명(Secret file) | `app-env` | `4_Web/.env` 전체 — 아래 웹 표의 키 |
| 자격증명(Secret file) | `emqx-env` | `3_FMS/infra/emqx/.env` — 아래 MQTT 표의 키 |
| 자격증명(Secret file) | `k3s-kubeconfig` | EC2 `/etc/rancher/k3s/k3s.yaml` (서버 `127.0.0.1:6443`) |

## 1-5. 배포

### 평소 배포 — release 머지 한 번

1. 기능 브랜치 → `develop` MR 머지 → `develop` → `release` MR 머지.
2. Jenkins 작업 `santafactory-deploy`(Jenkinsfile) 가 돈다(트리거는 Jenkins 작업 설정에 있다). 첫 단계가 브랜치를 보고 `release` 가 아니면 아무것도 하지 않는다.
3. 지난 배포 SHA 이후 바뀐 경로로 대상을 고른다: `4_Web/SantaFactoryBE|pdf|k8s` → 백엔드, `4_Web/SantaFactoryFE|k8s` → 프론트, `3_FMS/`(emqx·docs 제외) → DES 워커 + fms-core, `3_FMS/infra/emqx/` → EMQX, `3_FMS/host_orch/` · `compose.host-orch.yml` · `host_orch.Dockerfile` → host-orch. `Jenkinsfile`·`4_Web/docker-compose.yml` 이 바뀌면 전체.
4. 단계: **DB 덤프**(백엔드 배포 때만, 실패하면 중단) → 백엔드·PDF 빌드·k3s 롤링 → 프론트 빌드·k3s 롤링 → DES 워커 빌드·레지스트리 push·k3s 롤아웃(12개 준비 확인) → EMQX → fms-core → host-orch → 이미지 정리(빌드 태그 3개 보관).
5. 확인: 화면 로그인·견적, `sudo kubectl -n web get pods`, `sudo kubectl -n fms get pods -o wide`(12개 Running), `docker exec a106-rabbitmq rabbitmqctl list_queues name consumers`(`sim.request` 12).

### GPU 러너 — 손 배포 (Jenkins 대상 아님)

GPU 서버에서: 저장소 트리를 `~/deploy/S15P21A106` 으로 맞춘 뒤(맵 데이터 4개 `3_FMS/map/{occupancy_grid.npy,stations.json,charge_zone.json,rack_buffers.json}` 포함)
`docker compose -f 2_Simulation/t3_amr/deploy/compose.yml build` → `up -d`. 러너 여러 대는 `--profile multi`(노드 `sim-runner-gpu02`, EMQX 계정 · `HOST_ORCH_NODES` 추가 필요).
엣지가 EMQX 에 `NBIRTH` 를 보내면 host-orch 가 노드를 인식한다. 자세한 내용 `2_Simulation/t3_amr/deploy/README.md`.

## 1-6. 배포 시 특이사항

- **GPU 검증이 도는 중에는 host-orch 가 재시작되는 release 를 하지 않는다.** host-orch 가 다시 뜨면 진행 중이던 검증 작업이 고아가 된다. `3_FMS/host_orch/` 가 바뀌지 않은 release 는 host-orch 를 건드리지 않는다.
- **DB 는 손대기 전에 덤프한다.** Jenkins 가 백엔드 배포 앞에서 자동으로 뜨고(`/var/lib/jenkins/db-backup`), 실패하면 배포를 멈춘다. 되살리기: `docker exec -i a106-db sh -c 'pg_restore -U "$POSTGRES_USER" -d "$POSTGRES_DB" --clean --if-exists' < <덤프>`. `flyway_schema_history` 는 지우지 않는다(스키마 기준이 사라진다).
- **RabbitMQ 는 `hostname: rabbitmq` 를 고정한다.** 계정·큐가 노드 이름 폴더에 저장되어, 이름이 바뀌면 손으로 만든 `sim-worker` 계정이 사라지고 워커가 `ACCESS_REFUSED` 로 멈춘다(2026-09-23 장애). 사라졌으면 `4_Web/k8s/README.md` 의 재생성 명령.
- **k3s 파드 → compose 서비스는 도커 게이트웨이 `172.18.0.1`** 로 붙는다(`4_Web/k8s/compose-services.yaml`). 게이트웨이가 다르면 compose·매니페스트 주소를 맞춘다.
- **NodePort 를 쓰지 않는다.** EC2 보안그룹이 전 포트 개방이라 NodePort 는 인터넷에 열린다. 외부 입구는 Nginx 443 하나이고 파드는 고정 ClusterIP 로 받는다.
- **ufw 는 SSAFY 안내대로만 다룬다** — `ufw allow` 로 추가, `ufw status numbered` → `ufw delete <번호>` 로 삭제. `reload`·`enable`·`disable`·예약 실행은 하지 않는다(22 번이 끊기면 서버 초기화밖에 없다).
- **DES 워커 환경 변수는 세 곳이 같아야 한다** — k8s Deployment, `compose.estimate.yml`, `compose.estimate.gcp.yml`. 한 곳만 바꾸면 워커마다 견적 결과가 달라진다.
- **DES 규칙이 바뀌는 release 뒤에는 견적을 새로 돌린다.** 저장된 견적·검증은 그때의 결과 그대로다(검증은 그 견적의 DES 궤적을 재생한다).
- **Flyway 파괴적 마이그레이션**(컬럼 삭제·타입 변경)을 내는 release 는 롤링 중 두 백엔드가 같은 스키마를 못 쓰므로 `4_Web/k8s/backend.yaml` 의 `maxSurge` 를 0 으로 둔다.
- **GPU 러너** — compose 의 GPU capability 에 `ngx` 가 있어야 영상 노이즈가 없다. `devices:` 에 `/dev/nvidia*` 를 명시해 두어야 호스트 `systemctl daemon-reload` 뒤에도 GPU 접근이 살아 있다. 러너 한 대당 RAM 약 16 GB · VRAM 약 5 GB(이 서버는 2대까지).
- **GPU 서버 ↔ EC2 는 아직 Tailscale 사설망(tailnet)** 위다 — MQTT 1883 · MinIO 9002 업로드. 다른 GPU 서버로 옮기면 공인 경로(TLS · 출발지 제한 · 전용 계정)를 따로 열어야 한다. RT 코어가 있는 GPU(RTX · L4 · L40S)만 Isaac 렌더링이 된다(A100 · H100 불가).
- **GCP 노드는 Spot** 이라 회수될 수 있다. 회수되면 그 노드 몫 워커 4개가 Pending 이었다가 새 VM 이 합류하면 뜬다. 사라진 노드 객체는 `kubectl delete node <이름>`.
