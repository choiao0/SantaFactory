## 0. 요지

1. 선반을 얹은 AMR 이 제자리 회전을 하면 앞단 모서리가 **반경 558.7 mm** 의 원을 그린다.
   이 원이 자기 칸을 안 벗어나려면 격자가 **1,117.3 mm** 보다 커야 한다.
2. **1.0 m 격자는 58.7 mm 를 침범한다.** 1.2 m 는 성립하는 가장 가까운 0.1 m 배수다 (여유 41.3 mm).
3. **선반이 없어도 1.0 m 는 7.7 mm 모자란다.** 선반 때문에 생긴 문제가 아니다.
4. 격자가 다르면 칸 좌표계가 달라서 **"같은 경로"라는 비교 자체가 성립하지 않는다.**
   두 격자의 칸 중심은 한 번도 겹치지 않는다 (최근접 100 mm).
5. 대신 **정책·KPI 는 맞출 수 있고 맞춰 두었다.** 남은 동작 차이는 **토트 합승(`capacity`/`riders`)** 하나다 (§6).

## 1. 제자리 회전이 격자 하한을 정한다

PIBT 헤딩 모델은 로봇 한 대를 **칸 2개**(구동축 칸 + 뒤 칸)로 잡고, 90° 회전할 때 뒤 차체가
쓸고 가는 **칸 3개**를 예약한다. 이 모델이 성립하려면 회전 중에 **앞단이 자기 칸 밖으로
나가지 않아야** 한다. 앞단이 옆 칸으로 삐져나오면 예약하지 않은 칸을 차체가 점유한다.

구동축이 칸 중심에 있고 그 자리에서 도는 동안, 앞단 모서리가 그리는 원의 반지름은
앞길이와 반폭의 빗변이다.

```
회전 반경    R = hypot(front_len, width/2)
               = hypot(0.390, 0.400) = 0.558659 m

성립 조건    R < pitch / 2
→ 격자 하한   pitch > 2R = 1.117318 m
```

반대쪽 끝에서는 **상한**이 걸린다. 뒤 차체가 이웃 칸에 닿아야 "뒤 칸 1개" 모델이
성립하므로, 격자가 뒤길이의 두 배를 넘으면 안 된다.

```
상한         pitch < 2 x rear_len = 2 x 1.110 = 2.220000 m

유효 구간     1.117 m < pitch < 2.220 m
채택          pitch = 1.2 m   (여유 +41.3 mm)
```

축척으로 보면 (1 칸 = 10 mm, 구동축에서 바깥 거리):

```
        |---------+---------+---------+---------+---------+---------+
R 558.7 ########################################################        회전 반경
1.0 m/2 --------------------------------------------------|             X  58.7 mm 부족
1.2 m/2 ------------------------------------------------------------|   O  41.3 mm 여유
        0         100       200       300       400       500       600  [mm]
```

`RobotGeom.audit()` 의 `short_stays_home` 항목이 이걸 검사한다.

### 1-1. 이 하한은 모델 조건이자 **접촉 조건**이다 (2026-09-14 측정 추가)

위 유도는 "예약하지 않은 칸을 차체가 점유한다"는 **모델 성립 조건**이다. 그것만으로는
"실제로 부딪히느냐"에 답하지 못한다. 칸이 겹치는 것과 차체가 닿는 것은 다르기 때문이다
(우리도 한 번 이걸 혼동해서 차체가 568 mm 떨어진 사건을 겹침으로 잡은 적이 있다).

그래서 `RobotGeom.body_gap()` 으로 **차체 간 최소 거리**를 직접 쟀다. 두 경우가 갈린다.

**(가) 이웃이 서 있을 때 — 1.0 m 도 안 닿는다**

회전하는 A 옆에, 예약칸이 A 와 겹치지 않는(=계획이 허용하는) 모든 배치의 이웃 B 를 놓고
A 의 회전 전체를 훑었다.

| pitch | 합법 배치 | 접촉 | 최악의 차체 간격 |
|---:|---:|---:|---:|
| 1.0 | 172 | **0** | +41.3 mm |
| 1.1 | 172 | **0** | +141.3 mm |
| 1.2 | 172 | **0** | +241.3 mm |

```
간격 = pitch − R − 폭/2 = pitch − 0.558659 − 0.400 = pitch − 0.958659
→ 정지한 이웃에 닿으려면 pitch < 0.959 m
```

즉 이 경우만 보면 1.0 m 도 물리적으로는 통과한다. **이것만으로 1.0 을 반대하면 근거가
틀린다.**

**(나) 이웃도 같이 돌 때 — 여기서 닿는다**

ADG 에는 시간표가 없다. 예약칸이 겹치지 않는 두 회전에는 순서를 매기지 않으므로 **동시에
일어날 수 있다.** 그러면 두 앞 모서리가 각각 R 씩 마주 뻗어 합이 2R 이 된다.

| pitch | 동시회전 합법쌍 | 접촉 | 최악의 차체 간격 |
|---:|---:|---:|---:|
| 1.0 | 320 | **8** | 겹침 |
| 1.1 | 320 | **8** | 겹침 |
| 1.2 | 320 | **0** | **+82.8 mm** |

1.2 의 82.8 mm 가 `pitch − 2R = 1.200 − 1.117318 = 82.7 mm` 와 일치한다(표본 32개의
이산화 오차). **2R 은 모델 조건이기 이전에 접촉 한계 그 자체다.**

파괴 구성도 특정된다 — A 가 (5,5) 에서 1→0 으로, B 가 **(5,6) 에서 0→3** 으로 동시에
도는 경우다. 두 예약칸이 서로소라 ADG 가 순서를 매기지 않는다.

**재현**

```bash
source paths.sh
python - <<'PY'
import sys, os
sys.path.insert(0, os.path.join(os.environ['W'], 'path'))
import pibt_core_v2                      # sys.modules["pibt_core"] 등록 — 먼저
from pibt_core import occupied, swing_cells
from isaac_drive import YAW, wrap
from pibt_scene import make_geom
S = 32
def poses(g, r, c, h0, h1):
    x, y = g.cell_center((r, c))
    a0 = YAW[g.phys_heading(h0)]
    a1 = a0 + wrap(YAW[g.phys_heading(h1)] - a0)
    return [(x, y, a0 + (a1 - a0) * i / S) for i in range(S + 1)]
def res(r, c, h0, h1):                   # audit() 의 model_turn 과 같은 정의
    return {(r, c)} | set(swing_cells(r, c, h0, h1)) | set(occupied((r, c, h0)))
for p in (1.0, 1.1, 1.2):
    g = make_geom(p)
    resA, pa = res(5, 5, 1, 0), poses(g, 5, 5, 1, 0)
    best, hits, total = (1e9, None), 0, 0
    for dr in range(-3, 4):
        for dc in range(-3, 4):
            for h0 in range(4):
                for h1 in ((h0 + 1) % 4, (h0 - 1) % 4):
                    r, c = 5 + dr, 5 + dc
                    if res(r, c, h0, h1) & resA:   # 겹치면 ADG 가 순서를 매긴다
                        continue
                    total += 1
                    d = min(g.body_gap(u, v) for u in pa for v in poses(g, r, c, h0, h1))
                    if d <= 0: hits += 1
                    if d < best[0]: best = (d, (r, c, h0, h1))
    print(f'pitch {p:.2f}  동시회전 합법쌍 {total:4d}  접촉 {hits:3d}  '
          f'최소 차체거리 {best[0]*1000:+9.1f} mm  @ B={best[1]}')
PY
```

`body_gap` 은 겹치면 0.0 을 돌려준다(침투 깊이가 아니다). 그러므로 표의 "겹침" 은
"0 mm 이하" 를 뜻한다.

## 2. 치수별 하한

**하한을 정하는 것은 앞길이와 폭뿐이다.** 뒤길이는 상한에만 관여한다. 그래서 선반 외형
1,500 mm 와 차체 1,420 mm 의 차이 80 mm 를 **전부 뒤로** 붙였다 — 앞에 나눠 붙이면 하한이 올라간다.

| 구성 | front | width | rear | 격자 하한 | pitch 1.2 | pitch 1.0 |
|---|---:|---:|---:|---:|---:|---:|
| 차체만 (선반 없음) | 0.390 | 0.650 | 1.030 | 1.0153 | **+92.3 mm** | **−7.7 mm** |
| 선반 · 앞뒤 40씩 (검토안) | 0.430 | 0.800 | 1.070 | 1.1746 | +12.7 mm | −87.3 mm |
| 선반 · 뒤로 80 (**채택**) | 0.390 | 0.800 | 1.110 | 1.1173 | **+41.3 mm** | **−58.7 mm** |

여유·침범은 **반 pitch 기준**이다 (`R` 대 `pitch/2`). 격자 치수로 환산하면 두 배 —
채택안의 1.2 m 여유는 82.7 mm 다.

읽어야 할 것 두 가지.

1. **선반이 없어도 1.0 m 는 7.7 mm 모자란다.** 이건 선반이 만든 문제가 아니다.
2. 검토안(앞뒤 40씩)은 1.2 m 에서 여유가 **12.7 mm** 밖에 없다. 1.0 m 를 깨뜨린 위반량
   7.7 mm 과 같은 등급이라 살얼음이다. 그래서 80 mm 를 전부 뒤로 보냈다.

## 3. 격자가 다르면 경로를 못 맞춘다

두 시뮬의 칸 중심이 실제 창고 좌표 어디에 찍히는지 보면 분명하다.

```
3_FMS    CELL_M 1.0 · OFFSET_M 0.4   ->  중심 x = c + 0.1
t3_amr   pitch  1.2 · origin 0.6     ->  중심 x = 0.6 + 1.2c
```

```
FMS  1.0 m  -|-------|-------|-------|-------|-------|-------|-------|-   중심 x = c + 0.1
t3   1.2 m  -----|--------|---------|---------|--------|---------|-----   중심 x = 0.6 + 1.2c
            0       1       2       3       4       5       6       7     [m]
```

**두 격자는 한 번도 같은 지점에 찍히지 않는다.** `c1 + 0.1 = 0.6 + 1.2*c2` 를 만족하는
정수 짝이 없기 때문이다 — 양변에 10을 곱하면 `2*c2 ≡ 5 (mod 10)` 이고, 좌변은 짝수,
우변은 홀수다. 패턴은 6 m 마다 되풀이되며 **가장 가까이 스칠 때가 100 mm** 다.

그래서 "같은 경로가 나오는가"는 **답할 수 없는 질문**이다. 두 시뮬이 말하는 `(r, c)` 가
서로 다른 물리적 지점이고, 한쪽 경로를 다른 쪽 칸으로 옮겨 적을 방법이 없다.
스테이션·충전존 같은 고정 지물도 각자 다른 칸에 스냅된다.

**대신 비교할 수 있는 것은 정책과 KPI 다.** 배차 순서, 우선순위, 교대 창, 주문 분포,
복귀 규칙은 격자와 무관하게 같게 맞출 수 있고 실제로 맞춰 두었다 (§5). 그래야 두 시뮬의
KPI 차이를 "물리 때문"이라고 말할 수 있다.

## 4. 이 하한이 실제로 문제가 된 적이 있는가

있다. 다만 **이산 시뮬에서는 안 드러난다.** 물리 바디가 없으니 차체가 삐져나와도 부딪힐
대상이 없다. 연속 시간으로 실행하는 순간 드러난다.

같은 계획·같은 주행에서 ADG 가 예약하는 칸의 **근거만** 바꿔 12대로 측정한 결과다
(2026-09-14 재측정: 접촉과 칸 공유를 나눠 셌다. 실제 창고 격자 · 실제 치수 ·
slip/lag 주입 · 시드 2 x 판 2).

| ADG 를 지은 근거 | 주행 | **접촉** | 칸 공유 | 완주 |
|---|---:|---:|---:|---:|
| 실제 스윕 `swept_cells()` | 4 | **0** | 0 | 4/4 |
| 코어 예약 `cells_hist` | 4 | **21,625** | 44,470 | 4/4 |

**접촉** 은 차체끼리 실제로 닿은 건수다(`body_gap() <= 0`). **칸 공유** 는 발자국 칸이
겹친 건수 — 접촉의 상한이지 접촉이 아니다. 두 값을 나눠 세는 이유는 우리가 한 번
혼동했기 때문이다: 칸은 공유하지만 차체는 568 mm 떨어진 쌍을 겹침으로 잡은 적이 있다.
이번 재측정에서도 `cells_hist` 쪽 44,470 건 중 절반가량은 접촉이 아니다. **그러나 나머지
21,625 건은 진짜로 닿는다.**

> 이전 판에는 이 표가 `6 주행 / 10,148` 로 적혀 있었다. 그 수치는 `overlap_events`
> (칸 공유)이고 접촉 수가 아니었다 (2026-09-14 정정). 결론은 바뀌지 않지만 근거의
> 종류가 달라진다 — 이제 "칸이 겹쳤다" 가 아니라 "차체가 닿았다" 이다.

두 근거 모두 **완주는 한다**(4/4). 운동학 드라이버에는 물리 바디가 없어 차체가 서로
통과하기 때문이다. Isaac 의 PhysX 아래에서는 같은 상황이 실제 충돌이 된다. 그래서
이 숫자는 "시뮬이 죽었다" 가 아니라 **"죽지 않고 통과했다"** 로 읽어야 한다.

전이 1,200건 중 **645건에서 예약이 실제 스윕보다 작았다** (`move` 618 · `reverse` 27).
그래서 t3_amr 은 ADG 를 코어 예약이 아니라 `RobotGeom.swept_cells()` 로 짓는다
(`path/isaac_drive.py:130-145`).

**재현**

```bash
source paths.sh
python tools/remeasure_adg_basis.py          # SEEDS=4 RUNS=2 로 늘릴 수 있다
python path/isaac_drive.py --sweep-audit     # 예약 vs 실제 스윕만 따로
```

> **이건 3_FMS 가 틀렸다는 뜻이 아니다.** 이산 시뮬레이터로서 그 모델은 옳다 — 틱 t 와
> t+1 의 점유만 겹치지 않으면 되고, 그 사이 시각은 모델에 없다. 부족한 것은 연속 실행용
> 예약이고 그건 주행 계층의 일이다. 다만 그 계층을 만들려면 격자가 유효 구간 안에 있어야
> 하고, 1.0 m 는 그 밖이다.

| 점유 모델 | 헤딩 2칸 | 헤딩 2칸 | 같음 |

배차를 `fms` 로 맞추면서 **처리량은 손해를 봤다** — 12시드 실측에서 완료 태스크
`robot_first` 175 대 `fms` 149 (9승 2패 1무, −17.4%). 그래도 기본을 `fms` 로 둔 것은
정책이 다르면 KPI 차이를 물리 탓으로 돌릴 수 없기 때문이다.
**시연 영상을 뽑을 때는 `robot_first` 가 낫다.**

## 6. 배차 함수는 왜 그대로 못 가져왔나

격자와 달리 이건 **기하 문제가 아니라 배선 문제**다. FMS `_try_assign_all`
(`3_FMS/sim_engine/kernel/core.py:251`) 은 순수함수가 아니라 커널 메서드라 본문이
FMS 쪽 자료구조에 묶여 있다.

```
FMS      robots[rid]["pos"]      위치가 로봇 딕트 안
t3_amr   self.states[a][:2]      위치가 별도 상태표
```

그래서 **정책 본문을 이식**했다 (`path/lifelong.py:354`). 순회 순서, 최근접 규칙, 즉시
도킹까지 그대로 옮기고 참조만 우리 자료구조로 바꿨다. 여기까지는 동작이 같다.
정책 교체는 별 파일(`path/dispatch.py`)로 뺐다 — `lifelong.py` 를 직접 고치면 FMS 와의
패리티가 조용히 깨지고, FMS 가 커널을 갱신해 다시 이식할 때 우리 변경이 덮인다.

같이 딸려 있던 두 조각은 떼어냈다.

- `_needs_charge` — 배터리를 들어내면서 없앴다 (의도한 것)
- **`capacity` / `riders` — 아직 안 들어왔다**

두 번째가 **남아 있는 진짜 동작 차이**다. FMS 는 같은 픽 칸에서 나가는 출고 태스크를
`capacity`(최대 `MAX_TOTES_PER_TRIP` = 6)까지 한 왕복에 **합승**시킨다. 우리 쪽은 태스크
하나가 왕복 하나다. **같은 주문 스트림을 줘도 왕복 수가 달라지므로 KPI 가 어긋난다.**
자료구조를 안 건드리는 변경이라 이식 가능하다.

반대로 **우리 쪽에만 있는 것**도 하나 있다 — 드롭 칸 도달성 검사다. 1.2 m 로 풀링하면서
칸 하나가 끊기면, 드롭 칸이 도달 불가인 태스크를 받은 로봇이 `TO_DROP`(RANK 1)으로
영구 정지하고 우선순위가 높아 남까지 막는다.

```
드롭 검사 없음   완료 6 · 대기 13   정지 발생
드롭 검사 있음   완료 7 · 대기  0   정지 없음
```

**격자가 달라서 생긴, 우리 쪽에만 필요한 보정이다.** FMS 에는 없어도 된다.

## 7. 선반 설계를 바꾸려면

치수를 건드리면 격자가 따라 움직인다. 바꾸기 전에 이 순서로 확인할 것.

1. **앞으로는 절대 늘리지 말 것.** `front_len` 은 하한을 직접 올린다. 현재 0.390 m 에서
   40 mm 만 늘려도 하한이 1.1173 → 1.1746 m 로 뛰어 1.2 m 여유가 41.3 → 12.7 mm 가 된다.
2. **폭도 하한을 올린다.** 반폭이 제곱으로 들어간다. 800 mm 는 이미 차체(650)보다 150 mm 넓다.
3. **뒤로 늘리는 것은 안전하다.** `rear_len` 은 상한(2 x rear)에만 관여하고 현재 상한은
   2.220 m 라 여유가 크다.
4. **바꿨으면 `RobotGeom.audit()` 를 돌릴 것.** `short_stays_home` 이 False 면 격자를 올려야 한다.
5. **격자를 올리면 통로가 막힐 수 있다.** 0.1 m 마스크를 pitch 격자로 풀링할 때 통행 가능
   칸이 줄어든다. `--pool` 방식과 함께 다시 봐야 한다.
