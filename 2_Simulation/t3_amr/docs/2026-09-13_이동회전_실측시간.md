## 2. 왜 평균속도가 최대의 절반인가

칸마다 정지하기 때문이다. 가감속으로 검산하면 실측과 맞는다.

```
직진  a_lin 0.8 m/s^2 로 0.9 m/s 까지    램프 1.125 s · 0.506 m  (양쪽 1.013 m)
      남은 0.188 m 를 0.9 m/s 로          0.208 s
      합계                                 2.458 s      실측 2.367 s

회전  a_ang 3.0 rad/s^2 로 1.75 rad/s 까지 램프 0.583 s · 0.510 rad (양쪽 1.021 rad)
      남은 0.550 rad 를 1.75 rad/s 로      0.314 s
      합계                                 1.481 s      실측 1.511 s
```

직진이 이론보다 0.09 s 빠른 것은 `GOAL_TOL = 0.4 m` 때문이다 — 칸 중심에 완전히 서지 않고
다음 칸으로 이어 붙는 구간이 섞인다. 회전은 이론보다 0.03 s 느린데 정지 판정 여유 안이다.

**둘 다 가감속이 지배한다.** 1.2 m 이동에서 등속 구간은 0.19 m (16%) 뿐이고,
90° 회전에서 등각속 구간은 0.55 rad (35%) 뿐이다.

## 3. 틱 단위로 환산

계획 모델은 **1틱 = 1행동**이다 — 전진 1칸 / 90° 회전 / 대기. `edge_cost = 1`,
`turn_cost = TURN_TICKS = 1`, `wait_cost = 1`, 후진만 `REVERSE_FACTOR = 3.0`.

```
명목 1틱 = pitch / v_max = 1.2 / 0.9 = 1.333 s
```

| | 명목 | 실측 | 비 |
|---|---:|---:|---:|
| 전진 1칸 | 1.333 s | 2.367 s | **1.78배** |
| 회전 90° | 1.333 s | 1.511 s | 1.13배 |

틱당 속력으로 보면:

```
전진   0.506 칸/s  =  0.507 m/s     (정지→정지 평균)
회전   0.662 회/s  =  59.6 도/s     (90도 기준)
```

> **틱과 벽시계는 1:1 이 아니다.** 계획 horizon 315틱이 실제로는 301.3 s 에 끝나 틱당
> 0.956 s 로 보이는데, 전진 한 번이 2.367 s 인 것과 모순이 아니다. ADG 는 **시간표가 아니라
> 순서**로 돌기 때문에 12대가 병렬로 움직이고 대기 틱은 시간을 안 쓴다. 0.956 은 집계
> 비율일 뿐 동작 소요시간이 아니다. (`README.md` 의 주행 파이프라인 절 참조)

## 4. `TURN_TICKS` 의 근거가 실측과 안 맞는다

`3_FMS/sim_engine/pibt/geometry.py:26`

```python
TURN_TICKS = 1   # 설계 §1: Isaac 실측 90° 회전 0.76 s → 1틱 (2026-09-03 확정, 이전 가정 2틱)
```

**실측은 1.511 s 로 적힌 0.76 s 의 약 두 배다.** 0.76 s 는 최고 각속도만으로 본 값으로
추정된다 — `(pi/2) / 1.8 = 0.873 s` 에 가깝고, §2 의 램프 계산을 넣으면 1.48 s 가 된다.
이번 측정 표본 54건의 p10 이 1.300 s 라 0.76 s 는 분포 밖이다.

### 그래도 `1` 이 `2` 보다 낫다

```
회전 1.511 s / 전진 2.367 s = 0.64
```

즉 회전은 전진보다 **싸다.** `TURN_TICKS = 1` 은 둘을 같게 보므로 회전을 1.57배 비싸게
치고, `2` 였다면 3.1배 비싸게 친다. **1 이 실측에 더 가깝다** — 결론은 맞고 근거만 틀렸다.

정확히 맞추려면 0.64 인데, 커널의 `turn_cost` 는 실수를 받으므로
(`lifelong.py:181` — `float(self.turn_ticks if turn_cost is None else turn_cost)`)
기술적으로는 넣을 수 있다. **다만 그러면 3_FMS 와 어긋난다.**
`docs/2026-09-13_격자_1.2m_근거.md` §5 의 "맞춘 것" 목록에서 하나가 빠지는 셈이라,
바꾸려면 양쪽을 같이 바꿔야 비교가 성립한다.

### 권고

값은 `1` 로 두고 **주석의 근거만 정정**한다. 3_FMS 쪽 파일이므로 그쪽 소유다.

## 5. 재현

```bash
# 자세 기록을 켜고 주행 (30 Hz)
PIBT_RECORD=$OUT/rec_pibt12.npz PIBT_RECORD_HZ=30 bash run_record.sh

# NPZ 구조: t (N,) · pose (N, 12, 3) = [x, y, yaw] · pose_alt 동일 · stage
```

분석은 구간 분할로 한다. 문턱을 잘못 잡으면 표본이 통째로 날아간다.

- **직진**: `v > 0.03` 또는 `|w| > 0.03` 인 구간 중 회전각 < 20° 이고 길이 0.8~1.6 m
- **회전**: `|w| > 0.03` **이면서** `v < 0.08` (제자리 회전만) 인 구간 중 회전각 ≥ 60°

> **문턱을 처음에 틀렸다.** 회전 판정을 `|w| > 0.2` 로만 잡았더니 가감속 램프가 잘려
> 회전각이 86.3° 로 나왔고, 반대로 `0.03` 만 쓰고 `v` 게이트를 안 걸었더니 직진과 회전이
> 한 구간으로 붙어 **회전 표본이 0건**이 됐다. 두 조건을 같이 걸어야 한다.
